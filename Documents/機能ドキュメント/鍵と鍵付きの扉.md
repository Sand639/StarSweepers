## この機能は何か

**鍵を拾って持ち運び、鍵付きの扉まで運んで開ける機能。**

- 鍵は**その辺に落ちている物**として置く
- **上半身（と合体した体）が F で持てる**
- 鍵を持ったまま扉に近づくと、**扉の色が変わる**
- **F を押すと、鍵が無くなって扉が開く**

**一度開けたあとは、鍵なしで開け閉めできる。**
扉に近づいて **F** を押すたびに、**元の場所へ戻る → また開く**を繰り返す。

> 鍵は「**その扉を使えるようにする**」ためのもので、
> 「開けっぱなしにする」ためのものではない。

> **持ち運びは、新しく作っていない。** すでにある「物を持つ機能」をそのまま使っている。
> そのおかげで、**下半身だけのときは鍵を運べない**という決まりが自動で効いている。

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| 鍵に近づく | 鍵の**色が水色に変わる**（持てる合図） |
| **F** | **鍵を持つ。** 手の前に浮いた状態になる |
| 鍵を持って扉に近づく | **扉の色が金色に変わる**（開けられる合図）。画面中央の照準も同じ色になる |
| **F**（扉を狙って） | **鍵が消えて、扉が上へ開く** |
| **F**（扉を狙っていない） | ふつうに鍵を置く |
| **鍵を使ったあと、扉を狙って F** | **扉が元の場所へ戻る**（鍵は要らない） |
| **もう一度 F** | **また開く。** 以降は何度でも開け閉めできる |
| 鍵を持たずに、**まだ開けていない**扉に近づく | **何も起きない**（色も変わらない） |

- **鍵を持ったまま Tab で下半身に切り替えても、上半身が持ったまま待っている**
- **合った鍵でないと色が変わらない。** 開かない扉に何度も F を押す、ということにならない
- **すでに鍵を使った扉には、鍵を使えない**（鍵を無駄にしないため）
- **一度開けた扉は、下半身だけのときでも開け閉めできる**（鍵を持つ必要がないため）

> **扉の正面で物を置きたいときは注意。**
> 開けられる扉を狙っていると F が扉のものになるので、
> **扉から目をそらしてから F を押す。**

### 鍵の種類を分けたいとき

鍵と扉の両方にある **`Key Id`** に、**同じ言葉**を入れる（例：`赤` `倉庫`）。

- 同じ言葉のものだけが合う
- **どちらかが空なら、種類を問わずに開く**
- 1組しか使わないなら、**両方とも空のままでよい**

## ステージに置く手順

Unityのメニューから置ける。**手で組み立てる必要はない。**

1. 置きたいシーンを開く
2. シーンビューを、置きたい場所の近くまで動かす
3. メニューの **`Tools > StarSweepers > アーカイブ > ロボットステージ > 鍵と鍵付きの扉を置く`** を実行

**鍵と扉が1組**で置かれる。そのまま再生すれば動く。位置は好きに動かしてよい。

**ロボットの側は何もしなくてよい**（`RobotRig` プレハブに機能が入っている）。

### 開き方を変えたいとき

扉が動く部分は、ボタンで動く壁と**同じ部品**（`MoveObject`）。
**位置だけでなく、回転や大きさでも開かせられる。**

| 設定 | 動き |
| --- | --- |
| 位置 (0, 3.2, 0) | **上へ持ち上がる**（初期値） |
| 位置 (0, −3.2, 0) | 床に沈む |
| 位置 (3, 0, 0) | 横にスライドする |
| **回転 (0, 90, 0)** | **横に90度開く**（蝶番のような扉） |

くわしくは `踏むボタンと動く壁.md` の「動く物（`MoveObject`）」を読むこと。

### 扉以外の物を動かしたいとき

`Unlocked`（開いたときにすること）に相手を繋げば、**扉以外でも動かせる。**
音を鳴らす・演出を出す、なども同時にできる。

### 鍵（`DoorKey`）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Key Id | **同じ言葉を入れた扉だけが開く。** 空ならどの扉でも開く | 空 |

> 鍵には `Grabbable`（持てる物の印）も付いている。
> 持ったときの位置や向きは、そちらで調整できる。

### 扉（`LockedDoor`）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Key Id | **この言葉と同じ鍵だけが使える。** 空ならどの鍵でも開く | 空 |
| Door | 開く扉（`MoveObject`）。空なら同じ物から自動で探す | 自動で入る |
| Lock Indicator | **鍵穴の印。** 開いたときに消える | 自動で入る |
| Unlocked | 開いたときにすること（音・演出など） | 空 |

### ロボット側（`RobotKeyUser`）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Reach | この距離まで近づくと鍵を使える（m） | 3 |
| Max Angle | **見ている方向**からどれだけずれていても使えるか（度）。頭が中心 | 80 |
| Use Key | 鍵を使うキー | F |
| Highlight Color | 開けられるときの扉の色 | 金色 |

## 仕組み（分かる人向け）

### 持ち運びは作っていない

鍵は **`Grabbable`（持てる物）** として作ってある。
**持つ・運ぶ・持ち替える・落とすは、すべて既存の機能がやっている。**

そのため、**「腕のある体だけが鍵を運べる」**という決まりを別に書く必要がなかった。
`HoldPoint` が入っている体だけが持てる、という1つの決まりで全部そろっている。

### 扉は当たり判定で探さない

シーンに出ている扉が自分を `LockedDoor.All` に登録しておき、**そこから探している。**
ロープと同じ考え方（当たり判定より距離のほうが確実、という教訓による）。

**距離は、扉の中心ではなく「一番近い場所」で測っている。**
中心で測ると、**大きな扉ほど届かなくなる**（端に立っても中心が遠いため）。

### 開けられない扉は、色が変わらない

**まだ鍵がかかっている扉は、合う鍵を持っているときだけ色が変わる。**
持っていないのに色が変わると、「開けられそうなのに開かない」と勘違いさせるため。

**鍵を使ったあとの扉は、鍵を持っていなくても色が変わる**（開け閉めできるため）。

### F キーの取り合い

同じ F キーを、**ロープ・物の持ち運び・鍵**の3つで使っている。
取り合いにならないよう、順番を決めてある。

| 状況 | F を押すとどうなるか |
| --- | --- |
| ロープにつかまっている／狙っている | **ロープ**が受け取る |
| **操作できる扉を狙っている**（鍵で開ける／開け閉めする） | **扉**が受け取る |
| それ以外 | **物を持つ／離す**が受け取る |

### 鍵の消し方

**いきなり消さずに、いったん離してから消している**（`RobotGrabber.ConsumeHeld`）。

持ったままの物を消すと、**当たり判定を無視する設定などが後始末されずに残る。**
離す処理を通してから消せば、その心配がない。

## できていないこと・既知の問題

- **まだ実際に遊んで確かめていない。** 届く範囲や、扉の開く速さは調整前の値
- **鍵を落とした場所が悪いと、取り返せなくなることがある**（穴に落とすなど）。
  拾い直せない場所を作らないように気をつけること
- **一度使った鍵は戻らない。** 扉は開け閉めできるが、**鍵をかけ直すことはできない**
  （かけ直したい場合は `Relock` を呼ぶ処理を足す）
- **扉の正面では、F が扉のものになる。** 扉の前で物を置きたいときは、目をそらしてから押す
- **鍵を持ったまま扉に体当たりしても開かない。** 必ず F を押す必要がある
- **閉じるときに間に物がいても止まらない。** そのまま押し込む（動く壁と同じ）
- **鍵が1つの扉に1本、という管理はしていない。** 同じ `Key Id` の鍵が2本あれば、
  どちらでも開けられる（余った鍵はそのまま残る）
- 画面中央の照準は、**持てる物・ロープ・扉で色を取り合うことがある**（同時に近くにあるとき）。
  見た目だけの問題で、操作には影響しない
- 通信（マルチプレイ）には**未対応**。いまは1人用の作り
