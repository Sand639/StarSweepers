## この機能は何か

**ロボットの体を上半身と下半身に切り離して、それぞれを別々に操作できる機能。**

合体ロボのような遊びを試すためのプロトタイプ。
「上半身だけで狭い所に入る」「下半身だけを先に行かせる」といった遊びを想定している。

**カメラは操作している方を追いかける。** 切り替えると滑らかにそちらへ移る。

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| **W / A / S / D** | いま操作している方を動かす |
| **Space** | **ジャンプする**（合体中と、分離中の下半身だけ） |
| **F** | **目の前の物を持つ／離す**（合体中と、分離中の上半身だけ）<br>目の前が**ロープ**なら、**つかまる／手を離す**<br>**鍵を持って鍵付きの扉**を狙っていれば、**扉を開ける** |
| **V** | **一人称と三人称を切り替える** |
| **マウス** | カメラを回す（**操作している方を追いかける**） |
| **Q** | **上半身と下半身を切り離す** |
| **Tab** | **操作する方を切り替える**（上半身 ⇔ 下半身） |
| **E** | 近づいていれば**合体する** |
| **Escape** | **ポーズ画面が開く**（`ポーズ画面.md`）。ポーズ画面は**どのシーンでも自動で用意される** |

- **ジャンプできるのは、合体しているときと、分離中の下半身だけ。**
  上半身だけのときは跳べない（脚が無いため）
- **物を持てるのは、合体しているときと、分離中の上半身だけ。**
  下半身だけのときは持てない（腕が無いため）。**ジャンプとちょうど逆**
- **ロープにつかまれるのも、合体しているときと、分離中の上半身だけ。**
  **ロープにつかまったまま Q を押すと、脚をその場に落として上半身だけで上れる。**
  詳しくは `Documents/機能ドキュメント/ロープの上り下り.md` を読むこと

### 画面中央のレティクル（照準）

**画面の真ん中に、小さな十字が出る。**
プレイヤーのプロトタイプと同じもの。

**持てる物を狙えているときは、色が水色に変わって少し大きくなる。**
一人称ではマウスカーソルが消えているので、これが無いと狙いが分からない。

### 一人称と三人称（V キー）

| | 見え方 | 向いている場面 |
| --- | --- | --- |
| **三人称**（最初はこちら） | 体の後ろからカメラが見る | 全体が見えて動かしやすい |
| **一人称** | 体の目の位置から見る | **狙いやすい。隙間を通るときに分かりやすい** |

- **一人称のときは、操作している体の見た目が消える。**
  そうしないと、目の位置から自分の体の内側が見えてしまう
- **操作していない体は消えない。** 分離中に相手を見失わないようにするため
- **目の高さは体ごとに違う。** 合体時は1.82m、上半身だけだと0.72m。
  上半身だけのときは、視点がぐっと低くなる

### 動かし方はフォートナイト型

**一人称でも三人称でも、体は常に「カメラの向いている方向」を向く。**
進む方向へ向き直る作りではない。

そのぶん、**進む向きによって速さが変わる。**

| 進む向き | 速さ | 意味 |
| --- | --- | --- |
| **前** | **そのまま**（100%） | 一番速い |
| **横**（左右キー） | **50%**（**合体時は70%**） | 前と比べて50%減 |
| **後ろ** | **70%**（**合体時は50%**） | 前と比べて30%減 |

斜めのときは、前後と左右の割合で混ぜる（「斜め前」なら前と横の中間）。

> **向きが固定されているからこそ、この差が付けられる。**
> 進む方向へ向き直る作りだと、常に「前」に進んでいることになるので差が出ない。

**元の作り（進む方向へ向き直る）に戻したいときは、**
`RobotRig > Robot View Switcher > Face Look Direction` を OFF にする。

### 切り離したときの飛び方

**Q を押した瞬間に押しているキーの方向へ、上半身が飛ぶ。**

| 押しているキー | 上半身が飛ぶ方向 |
| --- | --- |
| **W** | 前 |
| **S** | 後ろ |
| **A / D** | 横 |
| 斜め（W+D など） | その斜め方向 |
| **何も押していない** | **真上だけ**（横には動かない） |

- 勢いは**だんだん弱まる**。壁があればぶつかって止まる
- **下半身はその場に残る**

> **飛ばす方向は「移動の入力」で決まる。** 体の向きではない。
> 体はカメラの向きを向いているので、**W はいつも画面の奥へ飛ぶ。**

### 出てくる高さは自動で決まる

**決め打ちの数字ではなく、体の大きさから計算している。**

```
合体した体の高さ（2.0m） − 上半身の高さ（0.9m） ＝ 1.1m
```

これは、**合体していたときに上半身の足元があった高さ**そのもの。
つまり**「その場から、そのまま外れて出てくる」**ことになる。

**体の大きさを変えても、位置がずれない。**
自分で決めたい場合は `Auto Split Height` を OFF にして、
`Upper Split Height` に数字を入れる。

### 物の持ち方

| | |
| --- | --- |
| 狙う | **持てる物に近づくと、その物の色が水色に変わる**（狙えている合図） |
| 持つ | **F** を押す。手の前に浮いた状態になる |
| 離す | **もう一度 F** を押す。その場に落ちる |

- 届く範囲は `Reach`（初期値2m）以内で、見ている方向から `Max Angle`（初期値70度）以内（頭を中心に測る。プレハブでは調整済み）
- **持ったまま切り替えても、持ち続ける。**
  上半身に持たせたまま、下半身を操作しに行ける
- **合体・分離で体が入れ替わったときは、持ち替える。**
  持てる体がいなくなった場合だけ、その場に落ちる
- **離せるのは、持っている本人だけ。**
  上半身が持っている物を、下半身を操作しながら離すことはできない

### 分離と合体のきまり

- **操作していない方はその場で止まる。** 勝手に動き回らない（重力では落ちる）
- 合体できるのは、次の**2つを両方とも満たす**とき
  - **真上から見たときの距離**が決めた値以内（`Combine Distance`。初期値2.5m）
  - **高さの差**が決めた値以内（`Combine Height Gap`。初期値1.5m）
  - まっすぐな距離ひとつで見ないのは、**「足元は近いが、高い足場の上にいる」を弾くため**
- 合体すると、**下半身のいた場所に合体した姿が現れる**

### 大事な作り

**合体しているときは1体、分けたときは2体**という作りにしている。

2つの体を物理的に繋いだまま動かすとガタつくため、**繋ぐのをやめて
「合体した姿の体」と「上半身」「下半身」を入れ替える**方式にした。
見た目は繋がったり分かれたりしているが、中身は入れ替わっている。

### 3つの状態

| 状態 | 意味 |
| --- | --- |
| `Combined` | 合体中。1体として動く |
| `SplitUpper` | 分離中。上半身を操作している |
| `SplitLower` | 分離中。下半身を操作している |

## すぐ試す方法

1. Unityで `Assets/Scenes/Test/RobotSplitTest.unity` を開く
2. **再生ボタンを押す**

シーンには次のものが置いてある。

- **低い隙間**（正面）… 合体したままでは通れず、**上半身だけなら通れる**
- **低い段差**と**高い段差**（左右）… 登れる高さの違いを試せる
- **目印の箱**（奥）… 分かれたまま歩き回るときの目安
- **紫の箱3つ**（手前）… **持てる箱**。大きさと重さが違う

次のような動きが試せる。

- 上半身だけで隙間を抜けて、下半身を呼び戻して合体する
- 上半身だけで箱を持って、隙間を抜けて運ぶ
- **W を押しながら Q** で、前方へ上半身を飛ばして届かない所へ渡す

```

│                              ／ RobotViewSwitcher（一人称・三人称）
├── ReticleCanvas           ← 画面中央の照準
│   └── Reticle
├── CameraRig               ← RobotCameraLook（左右の向き＋追いかけ）
│   └── CameraPivot         ← 上下の首振り
│       └── RobotCamera     ← カメラ
├── CombinedBody            ← 合体した姿。CharacterController / RobotBody
│   ├── LowerVisual         ← 下半身の見た目
│   ├── UpperVisual         ← 上半身の見た目
│   └── HoldPoint           ← 持った物を置く場所
├── UpperBody               ← 分けたときの上半身
│   ├── Visual
│   └── HoldPoint           ← 持った物を置く場所
└── LowerBody               ← 分けたときの下半身
    └── Visual              ← **HoldPoint は無い（＝物を持てない）**
```

> **「下半身は物を持てない」は、`HoldPoint` が入っていないことで決まっている。**
> プログラムの中で状態を見て分岐しているのではない。
> **持てるようにしたければ、`HoldPoint` を作って `Robot Body > Hold Point` に入れるだけでよい。**

**3つの体のうち、いつも1つか2つだけが出ている。**

| 状態 | 出ている体 |
| --- | --- |
| 合体中 | `CombinedBody` だけ |
| 分離中 | `UpperBody` と `LowerBody` |

**カメラは体の子にしていない。** 体の子にすると、体が動くたびに引っ張られて
見た目がカクつくため、毎フレーム体の位置へ寄せていく形にしている。

## 仕組み（分かる人向け）

- 状態は **enum（`Combined` / `SplitUpper` / `SplitLower`）** で管理している（依頼時の設計どおり）
- **体を繋いでいない。** 3つの体を `SetActive` で出し入れして入れ替えている
- 切り離すときは、合体した体の**足元を基準**に上半身と下半身を置く。
  上半身は少し後ろに出すので、下半身の上に乗って動けなくなることがない
- 合体するときは、**下半身のいた場所**に合体した体を置く。向きは操作していた方に合わせる
- 動きは **CharacterController**。物理演算で押し合わないので、指示したとおりに動く
- 位置を変えるときは、CharacterController を**いったん切ってから**動かしている。
  動いている最中に位置を変えると暴れるため
- カメラは `LateUpdate` で体の位置へ寄せている。体を動かしたあとに動かす必要があるため
- ジャンプは、**指定した高さまで上がる速さを逆算**して入れている
  （`Mathf.Sqrt(高さ * -2 * 重力)`）。プレイヤーの操作キャラと同じやり方
- **空中では、入力で速さを少しずつしか変えられない**（Air Control）。
  地上では入力どおりにすぐ変わるので、**跳んだ瞬間の勢いが空中でも残る。**
  変えられる速さは「全速 ÷ 0.1秒 × Air Control」（1秒あたり）。0.3なら、止まった状態から全速まで約0.33秒、
  前に全速で跳んでから真後ろに全速へ切り返すには約0.67秒かかる。
  切り離しや爆弾で飛ばされた勢い（`Launch`）は別に足されるので、この影響を受けない
- **誰が跳べるかは `RobotController` が決めている。** 体の側（`RobotBody`）は
  「跳べと言われたら、地面に付いていれば跳ぶ」だけにしてある。
  上半身を跳べるようにしたくなっても、体の側を触らずに済む

### 参考コードから変えたところ

依頼時の設計（enum管理・分離と合体・非操作側の停止）は踏襲しつつ、
**実際に動かしたときの不具合を受けて、繋ぎ方と動かし方を変えた。**

| 変えた点 | 理由 |
| --- | --- |
| **Jointをやめて、1体/2体の入れ替えにした** | **合体中にガクガクしていたため。** Jointは2つを引っ張り合って位置を保つ仕組みで、そこへ毎フレーム速度を直接入れると計算がぶつかる |
| **Rigidbody → CharacterController** | 同上。物理で押し合わないので、揺れず確実に動く |
| **カメラを体の子から外して追従にした** | **視点が滑らかでなかったため。** 物理は固定間隔、描画は可変間隔で動くので、体の子だとズレが見える |
| **切り離す位置を離した** | **分割時にWASDで動かなかったため。** 上下の当たり判定が接していて押し合っていた |
| `Input.GetKeyDown` / `Input.GetAxis` → **Input System** | このプロジェクトは Input System に統一する決まりのため |
| 移動を **カメラの向き基準**にした | 参考コードは体の向き基準で、左右キーが回転も兼ねていたため操作しづらかった |
| 進む速さを**体ごとに持たせた** | 「上半身は遅い」といった差を後から付けられるようにするため |

### 拡張ポイント

分離・合体・切り替えのタイミングで**イベントが呼ばれる**ようにしてある。
エフェクトや音を足したいときは、これを購読すればよい（`RobotController.cs` にコメントあり）。

| イベント | いつ呼ばれるか |
| --- | --- |
| `Split` | 切り離した瞬間 |
| `Combined` | 合体した瞬間 |
| `ControlSwitched` | 操作する方が切り替わったとき |

`State`（いまの状態）と `CanCombine`（いま合体できるか）も公開してあるので、UI表示に使える。
**`FlatDistance`（真上から見た距離）と `HeightGap`（高さの差）**も公開してあるので、
「あと少しで合体できる」といった表示も作れる。

## できていないこと・既知の問題

- **大槻さんが遊んで確かめ、値を調整済み**（2026/9/4・9/7）。持ち上げ・一人称とレティクル・フォートナイト型の動かし方・切り離しの飛び方は確認が取れている。
  **ジャンプの高さ**と、**空中での操作（Air Control）**は確かめた記録が無い
- **物理で押されない。** CharacterController にしたため、他の物にぶつかられても動かないし、
  箱を押しのけることもできない。揺れないことと引き換えの割り切り
- **切り離した瞬間の演出（光・音）は無い。** 上半身が跳ねて外れる動きは2026/9/4に付けた（上の「切り離したときの飛び方」）
- ~~フォートナイト型の動かし方は未確認~~ → **2026/9/4に大槻さんが確認済み。** 速さの割合も調整済み（上の表）
- **三人称のカメラは体の真後ろにある。** フォートナイトのような
  「肩越し（少し右にずらす）」にはしていない。
  ずらすとレティクルの位置と実際に狙える方向がずれるため、まず真後ろで作ってある。
  **肩越しにしたい場合は、狙いの補正も一緒に考える必要がある**
- **一人称のとき、腕は出ない。** プレイヤーのプロトタイプのような
  「画面手前の腕」は付けていない
- ~~持ち上げは未確認~~ → **2026/9/4に大槻さんが確認済み。持てている**
- ~~一人称とレティクルは未確認~~ → **2026/9/4に大槻さんが確認済み**
- **持った物は壁をすり抜ける。** 持っている間は物理を止めているため。
  持ったまま壁に近づくと、箱が壁の中に入る。**プロトタイプでは困らないと判断した**
- **持った物と自分の体はぶつからないようにしてある。** そうしないと、
  自分の持った箱に押されて動けなくなるため
- **持てるのは1つだけ。** 両手で2つ持つことはできない
- **ジャンプは1回だけ。** 空中でもう一度押しても跳べない（二段ジャンプは無い）。
  また、**ジャンプの高さや操作感は再生して確かめていない**ので、
  低い／高いと感じたら `Jump Height` で調整すること
- **ジャンプで届く場所を試す足場が、検証シーンに無い。** 段差はあるが、
  「ジャンプしないと登れない高さ」の台は置いていない
- **上半身だけでも普通に歩ける。** 「脚が無いから遅い」といった差は付けていない。
  各体の `Robot Body > Move Speed` を変えれば差を付けられる
- **合体は「真上から見た距離」と「高さの差」だけで判定している。** 向きは見ていないので、
  下半身の上に乗っていなくても近ければ合体できてしまう
- **合体する場所に物があっても合体できる。** 壁の中に現れることがありうる
- **アニメーションは無い。** 箱が滑るように動く
