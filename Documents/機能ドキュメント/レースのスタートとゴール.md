## この機能は何か

**マリオカートのような「スタートして、走って、ゴールする」の土台。**

カウントダウンのあとに走り出し、**コースを1周するとゴール**になる。
タイムと順位が画面に出る。

**あとでマルチプレイにする予定**があるため、
**1人でも複数人でも同じ形で動く**ように作ってある（下の「通信のための備え」を読むこと）。

> **中身はまだ「レースの骨組み」だけ。**
> アイテムも、加速パネルも、コンピューターの相手もいない。
> **順番の数え方と、勝ち負けの決め方**を先に作ってある。

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| **W / ↑** | アクセル |
| **S / ↓** | ブレーキ。止まっている間は**バック** |
| **A / D（← →）** | ハンドル |
| **R** | **やり直し**（スタート地点に戻る） |
| **Escape** | ポーズ画面（`ポーズ画面.md`） |

### 流れ

1. 再生すると、カートは**スタート地点に並んで止まっている**
2. **3・2・1** のカウントダウン。この間はアクセルを踏んでも進まない
3. **「スタート！」** で走り出せる
4. コースを**1周**すると **「ゴール！」** が出て、**タイムと順位**が表示される
5. **R** でいつでもやり直せる

### 画面に出るもの

| 場所 | 出るもの |
| --- | --- |
| 左上 | **周回**（1 / 1） |
| 右上 | **タイム** |
| 中央 | カウントダウン、ゴールの結果 |
| 右下 | 速度（km/h） |
| 左下 | 操作の案内 |

## コースの形

**陸上のトラックと同じ形。** 直線2本と、半円2つ。

| 項目 | 値 |
| --- | --- |
| 直線の長さ | 70m |
| カーブの半径 | 34m |
| 道の幅 | 16m |
| **1周の長さ** | **約354m** |

**手で並べていない。** 道・壁・通過点は、すべて**同じ計算式から位置を出している。**
手で置くと道と通過点がずれて、**「通ったのに数えてくれない」**という直しにくい不具合になるため。

大きさを変えたいときは `RaceCourseSetup.cs` の上のほうにある数値を変えて、
メニューの **`Tools > StarSweepers > アーカイブ > カーレース > レースの検証シーンを作り直す`** を実行する。

> **作り直すと、手で調整した内容は消える。** 実行する前に確認すること。

## 仕組み（分かる人向け）

### 1周をどう数えているか

**通過点（チェックポイント）を、順番に全部通ったら1周。**

コースには通過点が**6つ**あり、**0番がスタート／ゴールの線**。
カートは「次に通るべき番号」を1つだけ覚えていて、
**その番号の線を通ったときだけ**次へ進む。

```
スタート → 1 → 2 → 3 → 4 → 5 → 0（ゴール線）＝ 1周
```

こうすると**近道ができない。** 途中の壁を越えてゴール線へ戻っても、
4番や5番を通っていないので数えてもらえない。

> **スタート地点はゴール線の手前**にある。
> 走り出してすぐゴール線を通るが、そのときの「次の番号」は1番なので、**1周とは数えない。**

### 落ちたら戻す

**高さが Fall Height（初期値 -10）より下になったら、最後に通った通過点の少し手前に戻す。**
**周回の記録はそのまま**なので、落ちても1周がやり直しになることはない。

| 状況 | 戻る場所 |
| --- | --- |
| 通過点を1つ以上通った | **最後に通った通過点の、Respawn Back Distance だけ手前** |
| まだ1つも通っていない | **スタート地点** |

- 戻す場所は、**通過点の真下の地面を探して、その少し上**にする。地面が見つからなければ、通過点の高さのまま
- 向きは**通過点の進む向き**にそろえる（戻ったらすぐ走り出せる）
- **戻す場所は `RaceManager` を選ぶとシーンビューに黄緑の球で出る。** 落ちたと判定する高さは赤い枠で出る。
  通過点を置いたら、**球が床の上に乗っているか**を確かめること
- 瞬間移動で通過点を横切っても、**通ったことにはならない**（移動先を「前のフレームの位置」にしてから調べている）
- ロボットは、**分離中に操作していないほうの体が落ちても戻る**（出ている体のうち一番低いものを見ている）。
  戻すときは3つの体をまとめて戻す

### 当たり判定を使っていない理由

**速いと通り抜けるから。**

時速70kmだと1フレームで30cm以上進む。
薄い板に当たり判定を付けても、**その板を飛び越して次のフレームに行ってしまう**ことがある。

ここでは**「前のフレームの位置」から「今の位置」までの線が、通過点の面を横切ったか**を計算している。
**どれだけ速くても取りこぼさない。** 逆走して戻ってきた場合は数えない（向きも見ている）。

> **これは通信でも効く。** 通信では自分以外の当たり判定が消えていることがあり、
> 当たり判定に頼る作りは動かなくなる（`Documents/AIの申し送り.md` に失敗例あり）。

### 物理演算を使っていない理由

カートは **CharacterController** で動かしている。Rigidbody（物理演算）ではない。

- このプロジェクトでは、**物理と手動の動かし方を混ぜるとガタつく**ことが分かっている
- **物理は機械ごとに答えが少しずれる**ので、通信で位置を合わせにくい
- 壁で止まる・坂を登るは CharacterController がやってくれる

代わりに、**アクセルで速さが増え、ハンドルで向きが変わる**という単純な計算にしてある。

### 通信のための備え

**まだ通信は入っていない。** ただし、あとで入れやすい形にしてある。

| やっていること | なぜ |
| --- | --- |
| **周回を数えるのは `RaceManager` の1か所だけ** | **ホストの上だけで動かせば**、そのまま公平な判定になる |
| カート側は順位も周回も持っていない | 配る情報が「段階」と「周回数」だけで済む |
| 走っている人は**自分から名乗り出る**（`RaceRacer.All`） | 途中から参加した人も、探しにいかずに拾える |
| スタート位置を**4つ**用意してある | 人数が増えても並べ直すだけで済む |
| カメラとHUDは**「自分のカート」を選んで映す** | 通信で自分の1台だけ映せばよい |

## できていないこと・既知の問題

- **まだ実際に走らせて確かめていない。** 速さ・ハンドルの効き・カメラの距離は**調整前の値**
- **通信（マルチプレイ）は入っていない。** いまは1台だけ
- **コンピューターの相手（AI）がいない。** 順位は必ず1位になる
- **アイテム・加速パネル・ドリフトは無い**
- **コースは仮のもの。** 楕円を1つ置いただけで、高低差もショートカットも無い
- ~~**落ちたときの復帰が無い。**~~ **2026/9/14に対応済み。** 高さ -10 より下に落ちると、最後に通った通過点の手前に戻る（上の「落ちたら戻す」）
- **落ちずにコースの外へ出た場合は戻らない。** 高さでしか見ていないため。そのときは **R** で戻す
- **逆走の警告が無い。** 逆走しても止められないが、**周回にも数えられない**
- **音が鳴らない。** エンジン音もカウントダウンの音も無い
- **順位はゴールした順だけ。** 走っている最中の「今何位か」は出していない
  （1人しかいないため。通信を入れるときに足すこと）
- **タイヤは回らない。** 見た目だけの飾り
