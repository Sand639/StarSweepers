## この機能は何か

チームの**タスクリスト**（Google スプレッドシート）に入れた仕組み。

タスクは職能ごとの3枚の表（**プログラマー／デザイナー／プランナー**）に書く。
すると4枚目の **全体タスク** に、3枚分のタスクが**色・罫線・日付の表示・ドロップダウン（プルダウンの選択リスト）まで含めてそのまま**まとまる。

**向きは片方だけ。**

- 分表（3枚）を直す → 全体タスクに反映される ✅
- 全体タスクを直接直す → **次の同期で分表の内容に戻る**（分表への書き戻しはしない）❌

全体タスクは「自動でできる表示用の表」なので、**タスクは必ず分表に書くこと。**

---

## 職種をまたぐタスク（鏡像行）

**担当者に他の職種の人や「全員」を書くと、その職種の表にも同じ行が自動で現れる**仕組み。

例：プランナーの表に「動画作成／担当者＝チーム全員」と書く
→ プログラマーの表とデザイナーの表にも同じ行が入る。
例：プランナーの表に「デザイン部分のすり合わせ／担当者＝呉, デザイナ全員」と書く
→ デザイナーの表にも同じ行が入る。

こうなった行は **鏡像（きょうぞう）** と呼ぶ。元の行は **本体**。

### 「1か所直せば全部直る」

古い参考表は**同じ内容のコピーが3枚別々にあるだけ**だった（1枚直しても他は直らない）。
こちらは違う。**鏡像は本体の写し**なので、

- 本体（元の行）を直す → 鏡像も全部その内容に上書きされる
- 鏡像を勝手に直す → 次の同期で本体の内容に戻る（＝直せない）

**例外は E列（ステータス）だけ。** 鏡像のステータスを変えると本体に書き戻り、他の鏡像にも伝わる。
「自分の職種の分だけ進捗を付けたい」とき用の穴。

### 見た目と場所

- 鏡像行は**斜体**で表示される（本体と見分けるため）
- 挿入位置は**締切順**。自分の行の間に混ざって入る（一番下には溜まらない）
- 本体の行を削除すると、鏡像も一緒に消える
- 鏡像は**全体タスクには入らない**（本体がすでに入っているので、入れると重複するため）

### 既定はOFF

この機能は**入っただけでは動かない**。既定は OFF で、OFF の間はスクリプトが分表に行を足すことも消すことも一切ない。
ON にする前に、メニューの **「職種をまたぐタスク：予定を見る」** で
「どの名前がどの職種と認識されたか」「どの行が追加されるか」を**表を変えずに**確認できる。

## 使う人から見た動き

| 操作 | 結果 |
| --- | --- |
| 分表にタスク名（F列）を書く | 数秒以内に全体タスクに現れる |
| 分表の締切（D列）や担当者（G列）を変える | 全体タスクの並び順が組み直される |
| 分表のセルの色・罫線・日付の書式を変える | 全体タスクの同じ行にも写る |
| 分表の行を足す／消す | 全体タスクも作り直される |
| 全体タスクを直接編集する | 警告が出る（編集はできるが、次の同期で分表の内容に戻る） |
| 担当者に「チーム全員」や他職種の人を書く | （鏡像同期がONのとき）その職種の表にも斜体の行が入る |
| 鏡像行のステータス（E列）を変える | 本体に書き戻り、他の職種の鏡像にも伝わる |
| 鏡像行のステータス以外を変える | 次の同期で本体の内容に戻る（直せない） |
| スプレッドシートを開く | メニューに **「タスク同期」** が増える |

### メニュー（「タスク同期」）

- **今すぐ同期する（締切順に並べ直す）** … 待てないときに手で実行する
- **職種をまたぐタスク：予定を見る（表は変わりません）** … 名簿の認識結果と、追加・削除される鏡像行の一覧を出すだけ。**表は一切変更しない**
- **職種をまたぐタスク：自動反映をONにする** … 鏡像行を作り始める
- **職種をまたぐタスク：自動反映をOFFにする** … 止めたいとき。**すでに作った鏡像行は残る**（OFFの間は消さない）
- **初期設定をやり直す** … 表を作り直した・おかしな状態になったときに実行する。何回実行しても安全

### 全体タスクの並び順

1. **締切が早い順**（締切を書いていない行は一番下）
2. 締切が同じなら **職能**：プログラマー → デザイナー → プランナー
3. 職能も同じなら **担当者**：ドロップダウンの名单に並んでいる順
4. それでも同じなら **分表での行順**

**分表の行順は変えない。** 入力している最中に行が飛ぶと困るため。
並び替えた結果を見たいときは全体タスクを見る。

## 決まり（変えると壊れる）

| 項目 | 決まり |
| --- | --- |
| 列の役割 | A マイルステージ / B タスク属性 / C 親タスク / D 締切 / E ステータス / F タスク名 / G 担当者 / H 内容 / I 参考資料 |
| J列・K列（**全体タスク**） | **同期用の隠し列**（J＝どの分表か、K＝分表の行番号）。**触らない・消さない・列を挿入しない** |
| J列・K列（**分表3枚**） | **同期用の隠し列**（J＝タスクID、K＝種別「本体／鏡像」）。全体タスクの J/K とは**中身が別物**。**触らない・消さない・列を挿入しない** |
| 担当者の名单の並び | 「○○全員」が出てきてから次の「○○全員」までの名前が、その職種のメンバーとして認識される。**並びを入れ替えると名簿が変わる** |
| `外部者(ゲスト)` | どの職種にも属さない扱い（鏡像を作らない）。スクリプト内の `TASK_ROLELESS_OWNERS` で指定 |
| タスクの有無の判定 | **F列（タスク名）が空でない行**だけをタスクとして集約する |
| シート名 | `全体タスク` `プログラマー` `デザイナー` `プランナー` の4つ。名前を変えると動かなくなる |
| データ行 | 2行目〜1000行目 |
| ドロップダウン | 分表の B・D・E・G 列。**スクリプトは分表のドロップダウンを絶対に変えない**。全体タスクには3枚を合わせた名单を敷く |

## 仕組み（分かる人向け）

1. **トリガー** … `onEdit`（値の編集）と `onChange`（書式だけの変更・行列の挿入削除）の2つをインストール済み。
   `onEdit` は書式変更では発火しないので、色や罫線だけの編集は `onChange` の `FORMAT` で拾う。
2. **同期の単位は「行」** … Google Sheets API の `copyPaste`（`PASTE_NORMAL`）で分表の1行を全体タスクの1行に貼り付ける。
   これで**値・書式・数式・入力規則・結合セルがまとめて**移る。`setValues` だけでは書式が移らないので使っていない。
3. **行の対応表** … 全体タスクの J列（職能）・K列（元の行）が対応表。
   締切・タスク名・担当者以外の変更なら、並び順は変わらないので**その1行だけ**貼り直して済ませる（速い）。
   並び順に関わる変更や、行の増減なら全体を作り直す（`rebuildSummary_`）。
4. **全体タスクの直接編集** … 書き戻しはせず、`rebuildSummary_` で分表の内容を上書きし直す（＝実質元に戻る）。
5. **ドロップダウンの合併** … 分表3枚の2行目の入力規則を Sheets API で読み、候補を重複なく並べ替えずに連結して、
   全体タスクの B・D・E・G 列に `repeatCell` で敷く。データ行＋後ろの空行150行分まで敷くので、新しい行でも同じ名单が出る。
   中身が前回と同じなら書き直さない（`ScriptProperties` の署名で判定）。
6. **暴走防止** … `LockService` で二重実行を防ぐ。同期の直後に自分の書き込みで `onChange(FORMAT)` が返ってくるので、
   `CacheService` に10秒間の印を置いて無視する（これを外すと無限ループになる）。
7. **速度** … 以前は毎回999行×3枚読んでいたため1回の編集に3〜6秒かかっていた。
   `usedRowCount_()` で**実際に何か書いてある行まで**しか読まないようにした（2026/11/12）。
8. **鏡像行（職種をまたぐタスク）** … 行番号では対応付けできない（鏡像は表の途中に挿入されるので行がずれる）ため、
   本体行に**タスクID**を振って分表の J列に書く。K列に「本体」か「鏡像」かを書く。
   - 名簿は G列ドロップダウンの**並び順**から作る（`buildRoleMap_`）。名单そのものはスクリプトから変更しない。
   - 「やることリスト」を先に計算するだけ（`planMirrors_`）→ 表に書くのはその後（`executeMirrorPlan_`）。
     この2段構えのおかげで、**書く前に予定だけ確認できる**（メニューの「予定を見る」＝ `inspectMirrors()`）。
   - 実行順は ①本体にIDを書く → ②古くなった鏡像を**下の行から**削除 → ③行番号がずれるので読み直す
     → ④残す鏡像を本体で上書き → ⑤足りない鏡像を締切順の位置に挿入。
   - 鏡像の位置は `mirrorInsertRow_()` が「締切が自分より遅い最初の行」を探して決める。締切なしなら一番下。
   - 鏡像は斜体（`styleMirrorRow_`）。本体と見た目で区別できるようにするため。
   - 軽い変更（ステータス以外）は全体を作り直さず、`ScriptProperties` の索引（タスクID → 鏡像があるシート名）を辿って
     **その鏡像だけ**を上書きする（`refreshMirrorsOfSourceRow_`）。
9. **安全のための決まり** … スクリプトが分表で**削除・上書きするのは、K列に「鏡像」と書いてある行だけ**。
   印の無い行はすべて利用者自身のデータとして扱い、絶対に消さない。
   鏡像同期が OFF の間は `syncMirrors_()` が先頭で return するので、分表への書き込みは**ゼロ**。

## できていないこと・既知の問題

- **全体タスク → 分表 の書き戻しはしない**（仕様）。全体タスクに直接書いた内容は消える。
- 全体タスクには「自動生成です」という警告付きの保護をかけてあるが、**編集そのものは禁止していない**（警告だけ）。
  完全にロックすると、必要なときに手で直せなくなるため。
- 反映は**リアルタイムだが数秒かかる**ことがある。Google のトリガーの仕様で、連続して編集するとまとめて処理される。
- **Apps Script のスクリプト本体はリポジトリに入らない**。控え（`Documents/タスクリスト自動集約のコード.gs`）を手で合わせる必要がある。
- 分表の行を**まるごと削除**した場合は `onChange` で作り直すので問題ないが、
  分表の**シート名を変えたりシート自体を消したり**すると同期が止まる（`初期設定をやり直す` でも直らない。名前を戻すこと）。

### 鏡像行（職種をまたぐタスク）まわり

- **まだONにしていない。** 2026/11/13 に「予定を見る」で中身を確認した段階（本体10行・新規鏡像2件・削除0件）。
  実際に動かすにはメニューからONにする必要があり、**ONにしたあとの実地確認はまだ**。
- 鏡像行で**ステータス以外のメモを書いても残らない**（次の同期で本体の内容に戻る）。
  職種ごとに別の内容を書きたい場合は、鏡像ではなく**自分の表に別の行として書く**こと。
- 職種の判定は**担当者のドロップダウンの並び順**に依存している。
  並びを入れ替えると「誰がどの職種か」の認識が変わる。名簿が崩れたら「予定を見る」で確認できる。
- **`外部者(ゲスト)` はどの職種にも属さない**（鏡像を作らない）という前提で組んである。**この判断は未確認**。
  間違っていたら `TASK_ROLELESS_OWNERS` を直す。
- 鏡像は**表の途中に挿入される**ので、自分の行の行番号がずれる。数式や外部連携で行番号を固定指定している場合は注意。
  （この表には行番号の列は無いので、見た目の「第何タスク」は変わらない）
- 担当者に**名单に無い名前を手入力**した場合、その名前はどの職種にも属さないと判断されて鏡像は作られない。
- OFF にしても**すでに作った鏡像行は消えない**。消したいときは ON の状態で「今すぐ同期する」を実行する
  （本体が対象でなくなった鏡像だけが消える）。
