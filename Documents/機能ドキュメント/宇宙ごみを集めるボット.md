## この機能は何か

**プレイヤーの代わりに宇宙ごみ（素材）を集めて、自分のチームのゴールへ投げ入れる、コンピューターのキャラクター。**

いちばんの決まりは、**ボットはプレイヤーと同じ操作しかできない**こと（大槻さんの依頼）。
ボットは物を直接動かさず、**プレイヤーと同じ体に乗って、見えないコントローラーを操作するだけ**。
操作は **操作タイプA・投げ方「左右で使い分け」** と同じ。PCの設定がタイプBや ZRワンボタンになっていても、ボットはいつもこの操作で動く。

| ボットがすること | プレイヤーで言うと |
| --- | --- |
| 素材の近くの「投げればゴールに届く場所」まで歩く | 左スティック |
| 素材にカーソルを合わせる | 右スティック（マウス） |
| RT を押して溜め、フックが届く長さになったら離す | RT（右クリック）長押し → 離す |
| 持ち上げている間に、カーソルをゴールへ向ける | 右スティック |
| 投げるゲージが「ゴールまでちょうど届く強さ」の位置に来たら RT | RT |

ボットが見ているのは、**プレイヤーが画面で見ているものと同じ情報だけ**（素材とゴールの場所、自分のフックの溜め具合、投げるゲージの位置）。

> 2026/10/21 の最初の版は、素材を頭の上に直接くっつけて運ぶ形だった。
> 「プレイヤーと同じ操作しかできないNPCにしたい」との依頼で、同じ日にこの形へ作り直した。

## 遊ぶ人から見た動き

| こんなとき | ボットはどうするか |
| --- | --- |
| ラウンド中 | 近くの素材を右（RT）で撃って持ち上げ、ゲージを見て自分のゴールへ投げる。これをくり返す |
| 素材がゴールから遠い（1回では届かない） | ゴールに向けて思いきり投げて近づける（**中継**）。次にまたそれを拾う |
| 素材がゴールに近すぎる（いちばん弱く投げても飛びすぎる） | 素材の向こう側（ゴールから離れる側）に回ってから撃つ |
| フックを外した | もう一度撃つ。続けて外したら、その素材はしばらくあきらめる |
| 「引っ張る」ゲージが出た（横取りの待ちなど） | 真ん中あたりで LT を押す |
| ゴールのすぐ近くにある素材・重いデブリ | 狙わない |
| 進めなくなった | しばらくその素材をあきらめて、別の素材を探す |
| ラウンドの始まりの演出中・ラウンドの合間・ポーズ中 | 何もしない |

ゲージを押す位置は、**わざと少しぶらしてある**（Gauge Error）。毎回ぴったりにはならない。

### 試し方

1. Unity のメニュー **`Tools > StarSweepers > 宇宙ごみのボット > 検証シーンを作り直す`** を押す
2. できた `Assets/Scenes/Test/SpaceJunkBotTest.unity` を再生する
3. 青と赤のボットが、箱（素材）を右で撃って持ち上げ、自分の色の丸い印へ投げれば成功
4. 真ん中の **Player** は自分で動かせる（いつもの操作。ゲージも出る）。ボットと同じ遊び方を自分でも試せる

> 検証シーンのゴールは**ただの印**なので、点は数えない。つながずに動かしている。

## 設定できる値（インスペクターの項目）

`SpaceJunkBot` の項目。

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Team | どのチームのゴールへ運ぶか（**決まり：0=青 / 1=赤 / 2=緑 / 3=黄**） | 0 |
| Goal Override | ゴールを直接決める（検証シーン用）。入っていれば Team に関係なくここへ運ぶ。**マップでは空にしておく** | 空 |
| Hook / Thrower | 同じ体の HookController・ThrowController（空なら自動で探す） | 空 |
| View Camera | カーソルの位置を決めるカメラ。空なら Camera.main（**プレイヤーの狙いと同じカメラにすること**） | 空 |
| Hook Reach Use | フックの届く長さのうち、どこまで使うか。小さいほど近づいてから撃つ | 0.8 |
| Min Hook Distance | 素材にこれより近いと撃ちにくいので、これだけ離れて撃つ（m） | 2.5 |
| Misses Before Give Up | 同じ素材を続けて外したら、しばらくあきらめる回数 | 2 |
| Throw Range Use | 投げて届く最大の距離のうち、どこまで使うか。小さいほどゴールに寄ってから投げる | 0.85 |
| Throw Distance Scale | 飛ぶ距離の見積もりの補正。**いつも手前に落ちるなら大きく、奥へ行きすぎるなら小さく** | 1 |
| Gauge Error | ゲージを押す位置のぶれ。大きいほど下手になる。0 で毎回ぴったり | 0.04 |
| Ignore Near Goal Distance | ゴールからこの距離より近い素材は狙わない（m） | 2.5 |
| Think Seconds | 撃つ場所に着いてから、撃ち始めるまでの秒数 | 0.25 |
| After Throw Pause | 投げたあと、次を探し始めるまでの秒数 | 0.5 |
| Stuck Seconds | この秒数のあいだ近づけなかったら、その素材をあきらめる | 3 |
| Give Up Seconds | あきらめた素材を、また狙うまでの秒数 | 6 |

## 仕組み（分かる人向け）

- **入力の読み口（`PlayerInputSource`）に3つめの読み方を足した。** 体に `VirtualPlayerInput` が付いていると、
  移動・カーソル・LT・RT はすべてそこから読み、本物の機器（`Mouse.current`・`Gamepad.current`・キーボード）は読まない。
  `Gamepad` は null を返すので、移動と狙いは自然にタイプAになる。
  `ThrowController` の「タイプBの引き抜き」「ZRワンボタン」の判定も、`GameSettings` ではなく読み口の
  `ControllerOperation`・`ThrowOperation` を見るようにした（ボットはタイプA・左右で使い分けに固定）
- `SpaceJunkBot` は `[DefaultExecutionOrder(-50)]` で、操作の部品より先に動く。同じフレームに書き込んだボタンを、そのフレームのうちに部品が読むため
- ボタンは「押した瞬間」で判定されるので、ボットは押したら次のフレームで必ず離す（溜めている間だけ押し続ける）
- カーソルは、狙いたい地面の点を `Camera.WorldToScreenPoint` で画面の位置に直して置く（プレイヤーの狙いは、その画面の位置から地面へ線を伸ばして決まる）
- スティックは「画面の上下左右」なので、行きたい向きをカメラの水平の向きのぶんだけ逆に回して入れる
- 投げる強さの決め方：ゲージの真ん中への近さ → 力（`ThrowForceAtEdge`〜`ThrowForceAtCenter`）→ 物の重さで割って速さ → 頭上の高さから放物線（空気の抵抗も大まかに）で飛ぶ距離を見積もり、ゴールまでの距離にいちばん近くなる位置で押す。
  ゲージは出た直後に押しても効かない時間があるので、**いつも真ん中より右側で押す**
- 2体以上いても同じ素材を取り合わないよう、狙っている素材を `static` の一覧（`Reserved`）で共有している
- オンラインの体（`FishingNetPlayer`）に付けた場合は、持ち主のPCだけで考えるようにしてある（ただし下の「できていないこと」）

## できていないこと・既知の問題

- **Unity でまだ一度も動かしていない**（AI は Unity を開けないため。コンパイルだけ確認済み）
- **オンラインの試合にはまだ出せない。** ボット用のプレイヤーをホストが出す仕組み（参加番号・チーム分け・出てくる場所・カメラがボットを追わないようにする）が要る。次の段階
- 道を探さないので、ゴールとの間に穴や壁があるマップではうまく運べない。動く床・回る床・列車にも対応していない
- 飛ぶ距離の見積もりは計算だけなので、ずれていたら **Throw Distance Scale** で合わせる
- ボットのカーソルは、**このPCの画面（Camera.main）**を使って決める。カメラに映っていない場所（カメラの後ろ）は狙えない
- リアクションの円（`ReactionWheel`）を人が開いている間は、**ボットの狙いも止まる**（円が開いているかを全員で1つの値で見ているため）
- 引っ張る（LT で撃つ）操作は使わない。横取りの待ちで出るゲージにだけ LT を押す
- 見た目は仮（検証シーンでは、いつものプレイヤーの体をチームの色に塗っただけ）
