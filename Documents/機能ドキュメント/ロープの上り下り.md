## この機能は何か

**ステージに置いたロープにつかまって移動する機能。**

VALORANT のマップにある「上下に移動できる紐」と同じ役割。
**ジャンプでは届かない高さの足場へ上がる**ための道として使う。

**ロープは2種類ある。**「縦のロープ」は上り下り、**「横のロープ」はうんていのように伝っていく。**
どちらも同じ部品で、**置いたときの傾きだけで自動的に切り替わる。**

- ロープに近づいて **F** を押すとつかまる
- つかまっている間は **W で上、S で下**
- もう一度 **F** で手を離す（そのまま落ちる）
- **Space** を押すと、見ている方向へ飛び降りる

**つかまれるのは、合体しているときと、分離中の上半身だけ。**
**下半身だけのときはつかまれない。** これは「物を持てるのは腕のある体だけ」という
決まりと**まったく同じ仕組み**で決まっている（後述）。

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| **ロープに近づいて、レティクルを重ねる** | ロープの**色が黄色っぽく変わる**（つかまれる合図）。画面中央の照準も同じ色になる |
| **F** | **ロープにつかまる**。少しだけロープの方へ引き寄せられる |
| **W** | つかまったまま**上がる** |
| **S** | つかまったまま**下がる**。一番下まで下りると**自動で手を離して立つ** |
| **F**（つかまっている間） | **手を離す。**その場から落ちる |
| **Space**（つかまっている間） | **見ている方向へ飛び降りる。** 上の足場へ乗り移るときに使う |
| **Q**（つかまっている間） | **脚をその場に落として、上半身だけがロープに残る。** そのまま上り続けられる |
| **Tab**（つかまっている間） | 下半身の操作に移る。**上半身はロープにつかまったまま残る**（落ちない） |
| **E**（つかまっている間） | 合体するので、**手が離れる**（合体した体は脚の位置に出る） |

- **つかまっている間は、ロープに沿ってしか動けない**（縦のロープなら上下だけ）
- **両端で止まる。** ロープからはみ出して飛んでいくことはない
- **下半身だけのときは、近づいても色が変わらない**（つかまれないため）

### つかまれる条件は2つ

**次の2つを両方とも満たしたときだけ**つかまれる。

| 条件 | 見る場所 | 初期値 |
| --- | --- | --- |
| **手からロープまでの距離** | ロープの中で**手に一番近い場所** | **1.5m 以内**（`Reach`） |
| **画面の中央からのずれ** | ロープの中で**画面の中央に一番近い場所** | **10度以内**（`Max Angle`。プレハブの値。スクリプトの初期値は15度） |

**「近づく」だけではつかまれない。見て、狙う必要がある。**
逆に、遠くのロープを見ていてもつかまれない。

> **2つの条件は、別々に見ている。同じ場所で両方を満たす必要はない。**
> 斜めに走っているロープでは、**手に一番近い所と、画面の中央に映っている所が別**になる。
> 同じ場所を求めると、**画面では明らかに狙えているのにつかめない**、という状態になってしまう。

- 距離は**ロープ全体ではなく、一番近い場所まで**で測る。長いロープでも、目の前の部分でつかまれる
- **自分の体の裏を通っているロープも、真上を通っているロープもつかめる**（後述）

### 狙いは「カメラから見た角度」で測る

**カメラの位置から見て、画面の中央から何度ずれているか**で判断している。
カメラを中心にしているので、**画面のどのあたりに映っているか**とほぼ同じ意味になる。

**プレイヤーの頭を中心にしていないのが要点。**
頭を中心にすると、

- **自分の体の裏を通っているロープ**
- **真上を通っているロープ**

が「大きく外れている」と判断されてしまい、**画面では狙えているのにつかめない。**
カメラから測れば、**見えているとおり**になる。

> **物を持つ・扉を開けるほうは、いまも「頭が中心」。**
> こちらは**手を伸ばして触る**動きなので、頭からの向きで測るほうが自然なため。
> ロープだけ考え方が違う。

### 持ち上げ・扉のほうの判定（参考）

同じ「狙えているか」でも、**物を持つ・扉を開けるほうは中心が違う。**

| | 中心 | 理由 |
| --- | --- | --- |
| **ロープ** | **カメラ** | 細長くて、**体の裏や真上**を通ることが多いため |
| **持ち上げ・扉** | **プレイヤーの頭** | **手を伸ばして触る**動きなので、頭からの向きが自然なため |

頭を中心にするほうは、**カメラの向き**と**その水平の向き**の2本で調べていて、
どちらかに入っていれば狙えている扱いになる
（そのおかげで、**足元の物を見下ろさずに拾える**）。

**どちらも中身は `Assets/Scripts/Common/AimCheck.cs` にまとめてある。**

### 脚を置いて、上半身だけで上る（Q）

**ロープにつかまったまま Q を押すと、脚がその場に落ちて、上半身だけがロープに残る。**

- 落とした脚は**そのまま下まで落ちる**（重力で落ちるだけ）
- **上半身は、いた場所から動かない。** 押した瞬間に位置がずれることはない
- そのまま **W で上り続けられる**

このあと **Tab を押すと、上半身をロープに残したまま下半身を操作しに行ける。**
残した上半身は**落ちずに、その高さでつかまったまま**待っている。
もう一度 Tab を押せば、上半身に戻って続きを上れる。

> **上半身をロープに残している間、W / S / Space / F は下半身のもの**になる。
> 残した上半身が勝手に動くことはない。

### 横向きのロープ（うんてい）

**ロープを倒して置くと、「伝っていくロープ」になる。**

| | 縦のロープ | 横のロープ |
| --- | --- | --- |
| 置き方 | そのまま立てる | **横に倒す** |
| ぶら下がり方 | ロープの**横** | **ロープの真下** |
| 動かし方 | **W で上、S で下** | **行きたい方へ倒すと、その方向へ進む** |
| 端まで行くと | 一番下で自動的に手を離す | **止まるだけ**（落ちない） |

- **設定で切り替える必要はない。** 倒して置けば自動で横向きの動きになる
  （45度より寝ていれば横向き扱い）
- **斜めに置けば、その中間**になる
- 横のロープでは、**手がロープに届く高さにぶら下がる。**
  合体した体と上半身で背丈が違っても、同じ見た目になる

> **横のロープで「W で進む」にしていない理由。**
> 横のロープはどちらを向いてつかまるか分からないので、W/S だと
> **カメラの向きしだいで進む向きが逆になってしまう。**
> 「行きたい方へ倒せば、その方へ進む」ほうが迷わない。

### 物を持つのと同じ F キーを使っている

同じキーだが、**取り合いにならないように優先順位を決めてある。**

| 状況 | F を押すとどうなるか |
| --- | --- |
| ロープにつかまっている | **手を離す**（ロープが優先） |
| ロープを狙っている・物は持っていない | **ロープにつかまる**（ロープが優先） |
| すでに物を持っている | **物を離す**（持っている物が優先） |
| ロープを狙っていない | **目の前の物を持つ／離す** |

**ロープにつかまっている間は、物を持てない。**

## ロープをステージに置く手順

Unityのメニューから置ける。**手で組み立てる必要はない。**

1. ロープを置きたいシーンを開く
2. シーンビューを、置きたい場所の近くまで動かす
3. メニューの **`Tools > StarSweepers > アーカイブ > ロボットステージ > ロープを1本置く`** を実行

**画面が見ている場所の真下にある床の上**に、長さ6mのロープが立つ。
あとは Inspector で位置と長さ（`Height`）を直せばよい。**長さを変えると見た目も一緒に伸びる。**

**横向きのロープは、別のメニューから置ける。**

**`Tools > StarSweepers > アーカイブ > ロボットステージ > 横向きのロープを置く`**

床から2.8mの高さに、奥へ向けて6mのロープが渡る（合体した体が立ったまま届く高さ）。**向きを変えたいときは、そのまま回転させればよい。**
（縦のロープを自分で倒しても、同じものになる）

> ロボットの側は、`RobotRig` プレハブに機能が入っているので**何もしなくてよい。**
> もし外れてしまった場合は、`Tools > StarSweepers > アーカイブ > ロボットステージ > ロボットにロープ機能を足す` を実行すれば戻る。

## 設定できる値（インスペクターの項目）

### ロープ側（`RobotRope`）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Height | 根元から先端までの長さ（m） | 6 |
| Hang Distance | **縦のとき**、ロープからどれだけ離れてぶら下がるか（m） | 0.55 |
| **Hang Below** | **横のとき**、手からどれだけ下にぶら下がるか（m） | 0.15 |
| Bottom Margin | 根元から、ここまでは進めない余白（m） | 0 |
| Top Margin | 先端から、ここまでは進めない余白（m） | 0.2 |
| Visual | 長さに合わせて伸び縮みさせる筒 | 自動で入る |

**この部品を付けた物の位置が、ロープの下端になる。** そこから真上（その物の上向き）へ伸びる。
**傾けて置けば、斜めのロープにもなる。**

### ロボット側（`RobotRopeClimber`）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| **Reach** | **手からこの距離まで近づくとつかまれる（m）** | 1.5 |
| **Max Angle** | **画面の中央からのずれの限界（度）**。カメラから見た角度 | 15 |
| Climb Speed | 上り下りする速さ（m/秒） | 3.5 |
| Snap Speed | ロープまで引き寄せられる速さ | 8 |
| Release At Bottom | 一番下まで下りたら自動で手を離すか | ON |
| Jump Off Speed | Space で飛び降りるときに前へ飛ぶ勢い | 4 |

## 仕組み（分かる人向け）

### つかまれる体の決め方

**状態を見て分岐していない。**
`RobotBody` に「手の位置（`HoldPoint`）」が入っているかどうかだけで決まる。

合体した体と上半身には手が入っていて、下半身には入っていない。
**物を持つ機能とまったく同じ決まり**なので、あとから体を増やしても、
手を入れるかどうかだけで「つかまれる／つかまれない」が決まる。

### ロープは当たり判定を持たない

ロープは **Collider（当たり判定）を使っていない。**
探すときは、シーンに出ているロープが自分を `RobotRope.All` に登録しておき、**そこから探している。**

理由は2つ。

- **ロープに体がぶつかって、つかまる前に押し返されるのを防ぐため**
- ステージに置くロープはせいぜい数本なので、当たり判定で探すより軽いため

> 通信の実装のときにも「当たり判定で探すより、距離で探すほうが確実」という教訓があった。
> それと同じ考え方をしている。

### 動かし方

つかまっている間は、その体を `RobotController.SuspendedBody` に入れて
**普段の移動（歩く・落ちる）から外し、`RobotRopeClimber` が直接動かしている。**

両方が同時に動かすと**引っ張り合いになってガタつく**ため、
「動かすのは常にどちらか一方だけ」という形にしてある。

**「ON / OFF」ではなく「どの体か」を持たせているのが要点。**
操作していない体にも指定できるので、
**上半身をロープに残したまま、下半身を操作しに行っても落ちない。**

体を動かすのは `RobotBody.MoveWithoutGravity`。
落ちる勢いを毎回ゼロに戻しているので、**長くつかまっていても、
手を離した瞬間に急降下することはない。**

壁や天井にはぶつかる（`CharacterController` 越しに動かしているため）。
上れなかったぶんは、つかまっている高さにも戻して反映しているので、
**壁に阻まれたあとで一気に引き寄せられることもない。**

### 脚を置くとき（Q）の引き継ぎ

切り離しの処理そのものは変えていない。
**切り離した直後に、上半身をロープの位置へ戻している。**

同じフレームのうちに戻すので、画面上は「上半身は動かず、脚だけが落ちた」ように見える。
切り離しで与えられた飛ぶ勢いも、戻すとき（`Teleport`）に一緒に消える。

戻す高さは、**足元ではなく「手が握っている高さ」で合わせている。**
足元の高さをそのまま渡すと、**合体した体と上半身の背丈の差（1.1m）だけ体がずり落ちる**ため。

> 処理の順番が大事。**切り離しの合図（`Split`）を、体の入れ替えの合図（`ControlSwitched`）より先に受け取っている。**
> 逆だと、入れ替えの側が「つかまっていた体が消えた」と判断して手を離してしまう。

### ぶら下がる側

つかまった瞬間に、**体がロープのどちら側にいたか**を覚えておき、その側にぶら下がり続ける。
覚えずに毎回計算し直すと、**反対側へ勝手に回り込んで足場から落ちたように見えてしまう。**

## できていないこと・既知の問題

- **つかまる条件（`Reach` / `Max Angle`）は2026/9/7に大槻さんが遊んで調整した。** 上り下りの速さや、飛び降りる勢いは調整前の値のまま
- **ロープを壁の中や、足場のすぐ下に置くと、上がりきれずに引っかかる。**
  ロープの周りは少し空けて置くこと
- **上端まで上がっても、自動では足場に乗らない。** Space で飛び降りて乗り移る
- **落とした脚は、ロープの真下に落ちる。** 落ちた先が穴や水だった場合の扱いは決めていない
- **脚を置いたあと、上半身が上にいる状態で合体（E）すると、合体した体は脚の位置に出る。**
  上半身が下りてくる形になるので、**高い所で合体して足場に立つ、という使い方はできない**
- 画面中央の照準は、**持てる物とロープで色を取り合うことがある**（両方が近くにあるとき）。
  見た目だけの問題で、操作には影響しない
- 通信（マルチプレイ）には**未対応**。いまは1人用の作りになっている
