## この機能は何か

2つの機能をまとめて作った。

1. **席ごとの入力（ラッパ）**
   遊ぶ人1人ぶんを「席」（P1・P2…）として扱い、**キーボード＋マウスで遊んでも、コントローラで遊んでも、同じ書き方で読める**ようにする。
   ゲームのスクリプトは「どの機器か」を気にせず、「P1 の移動」「P1 がジャンプを押した」だけを読めばよい。
2. **機器の固定登録**
   これまでは「起動してから最初に押した順」でキーボード・マウスの番号が決まっていた。
   **一度登録すれば、次からは起動しただけで、決まったキーボード・マウスが決まった番号（席）になる**ようにした。

Windows は、つないだ機器を1台ずつ「デバイスパス」という名前で見分けている（`\\?\HID#VID_046D&PID_C52B&MI_00#7&2a3b…` のような文字列）。
この名前は**同じ USB の差し込み口に挿している限り、PC を再起動しても変わらない**ので、これを番号ごとに保存しておく。

## 遊ぶ人から見た動き

検証シーン `InputSeatTest.unity` での動き。

| 操作 | 結果 |
| --- | --- |
| キーボードのキーを押す／マウスを動かす | 押した順に P1・P2 に入る（登録していないとき） |
| コントローラのボタンを押す | 空いている席に入る（下の「コントローラの入り方」） |
| WASD／矢印、または左スティック | その席の四角が動く |
| マウス、または右スティック | その席のカーソル（十字）が動く |
| F6 | **固定登録を始める**。画面の案内どおり「P1 のキーボード → P2 のキーボード → P1 のマウス → P2 のマウス」の順に押すと、保存される |
| （登録中）登録済みのキーボードで Enter | その種類の登録をそこで終える（キーボードを使わない席がある場合など） |
| F7 | 登録をやめて、前の登録に戻す |
| F8 | 保存した登録を消して、押した順に戻す |
| F5 | 割り当てをやり直す（固定登録はそのまま。登録した機器はすぐ元の席に戻る） |

### コントローラの入り方

ボタンを押したコントローラが、次の順で空いている席に入る。

1. コントローラが外れた席（抜けたコントローラを挿し直したときに、元の席へ戻るように）
2. キーボードもマウスもコントローラも入っていない席
3. コントローラが入っていない席

**入った瞬間のボタンは、ジャンプなどの操作としては数えない**（一度全部離してから効く）。
コントローラは**固定登録の対象外**（下の「できていないこと」）。

### 使い方（プログラマー向け）

シーンに `InputSeatManager` を1つ置く（`MultiKeyboardManager` と `MultiMouseManager` が無ければ自動で同じ GameObject に作られる）。

```csharp
using ProjectEL4S.InputControl;

InputSeat seat = InputSeatManager.Instance.GetSeat(0);   // 0 = P1、1 = P2

Vector2 move = seat.Move;            // -1..1。WASD／矢印 か 左スティック（大きいほう）
Vector2 cursor = seat.Cursor;        // 画面上のカーソル（Screen 座標）。マウス か 右スティックで動く仮想カーソル
Vector2 aim = seat.AimStick;         // 右スティックの向き（マウスでは 0。マウスは cursor を使う）
Vector2 look = seat.LookDelta;       // 視点を回す量（ピクセル）

if (seat.WasPressedThisFrame(InputSeatButton.Jump)) { /* Space か A */ }
if (seat.IsPressed(InputSeatButton.Attack)) { /* 左クリック か LT */ }

if (seat.LastUsedScheme == InputSeatScheme.Gamepad) { /* ボタンの案内をコントローラ用にする */ }
if (!seat.HasAnyDevice) { /* この席には誰もいない */ }
```

**ボタンの初期の割り当て**（`InputSeatManager` のインスペクターの `Buttons` で変えられる）

| ボタン | キーボード | マウス | コントローラ（Xbox の呼び方） |
| --- | --- | --- | --- |
| Attack | ― | 左クリック | LT |
| Aim | ― | 右クリック | RT |
| Jump | Space | ― | A |
| Interact | E | ― | X |
| Sprint | 左 Shift | ― | 左スティック押し込み |
| Crouch | C | ― | B |
| Previous | 1 | ― | LB |
| Next | 2 | ― | RB |
| Pause | Esc | ― | Start |

マウスの左右を LT／RT にしたのは、釣りの操作（`ThrowController`：左クリック＝LT、右クリック＝RT）に合わせたため。
ボタンを増やしたいときは `InputSeat.cs` の `InputSeatButton` に名前を足し、`CreateDefaults` に初期の割り当てを足す。

## 設定できる値（インスペクターの項目）

`InputSeatManager`

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| Seat Count | 遊ぶ人数（席の数）。キーボード・マウスの管理役の台数もこの数以上にする | 2 |
| Seat Colors | 席ごとの色（確認用HUDの表示に使う） | 水色・橙・緑・黄 |
| Keyboards ／ Mice | 使う管理役。空ならシーンにある物、無ければ同じ GameObject に作る | 空 |
| Load Saved Registration | 起動したときに、保存してある固定登録を読み込む。切ると毎回押した順 | ON |
| Join Gamepads By Press | ボタンを押したコントローラを空いている席に自動で入れる | ON |
| Move Keys | 移動に使うキー（WASD／矢印／両方） | 両方 |
| Stick Deadzone | スティックのデッドゾーン | 0.15 |
| Gamepad Cursor Speed | 右スティックで動かす仮想カーソルの速さ（px/秒） | 900 |
| Buttons | ボタンごとのキー・マウスのボタン・コントローラのボタン | 上の表 |

`MultiMouseManager` に1つ追加

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| Assign On Click Only | クリックしたマウスだけ割り当てる（動かしただけでは割り当てない）。登録の途中は自動で ON になる | OFF |

## 仕組み（分かる人向け）

- **固定登録**
  - `MultiKeyboardManager.SetFixedDevices(名前の配列)` ／ `MultiMouseManager.SetFixedDevices(…)` で「i 番はこの名前の機器」を渡す。
  - 渡すと割り当てをやり直し、**今つながっている機器の一覧（`GetRawInputDeviceList`）から登録した機器を探して、押す前から割り当てる**。
  - 後から挿された機器や一覧取得に漏れた機器も、最初に押されたときに名前を比べて、登録した番号に入れる（大文字小文字は区別しない）。
  - **登録していない機器**は、固定登録の無い番号を先に使い、足りなければ「登録した機器がつながっていない番号」を使う。
    展示中にキーボードが壊れて別のものに替えても、その席で遊べるようにするため。
  - 名前を取るのは Windows への問い合わせになるので、ハンドルごとに覚えておく（読み取りを止めたら捨てる）。
- **登録の流れ**（`InputSeatManager.BeginRegistration`）
  1. 固定を外して割り当てを消す（ここからは押した順＝席の順）。マウスは「クリックしたときだけ割り当てる」にする。
  2. キーボードの番：席の数だけ割り当たるか、**前のフレームまでに登録済みのキーボード**で Enter が押されたら次へ。
     新しいキーボードの Enter は「登録」として扱う。
  3. マウスの番：入ったときにマウスの割り当てを一度消す（キーボードの番にクリックしたマウスを数えないため）。
     席の数だけ割り当たるか、Enter で終わり。
  4. その時点の名前を `InputSeats.json` に保存し、`SetFixedDevices` で固定し直す。
  - 登録中は、全部の席の入力を 0 にする（登録の操作でゲームが動かないように）。
- **席の入力**（`InputSeatManager.Update`、実行順は -90。管理役の -100 より後）
  - 移動：キーボードとスティックのうち大きいほう。ボタン：どれかで押されていれば押されている。
  - 1フレームの中で押して離した場合（キーボードの素早い連打）も、「押した」「離した」の両方が立つ。
  - カーソル：マウスが動いたらマウスの位置、右スティックが動いたら仮想カーソルを進める。持ち替えたときに飛ばないよう、
    スティックで動かしたらマウス側の位置もそろえる。カーソルは `Time.unscaledDeltaTime` で動く（ポーズ中も動く）。

## できていないこと・既知の問題

- **キーボード2台・マウス2台・コントローラを実際につないでの確認はまだ**（コンパイルと検証シーンの作成までは確認済み）。
- **同じ機種を2台使う場合、見分けられるのは「どの USB の差し込み口に挿したか」だけ。**
  差し込み口を変える・USB ハブを替える・ハブの別の口に挿すと、名前が変わって「登録したものが見つからない」になる。
  展示では、差し込み口に印を付けるなど、**挿す場所を変えない運用**が要る。→ `リスクリスト.md`
- 1つの受信機に複数の機器をつなぐワイヤレス製品では、分けて読めないことがある。
- **コントローラは固定登録できない。** Unity が付ける番号は起動するたびに変わり、Xbox のコントローラは機器ごとの名前も取れないため。
  コントローラは「ボタンを押した順」に入る。決まった席に入れたいときは `AssignGamepad(席, コントローラ)` を使う。
- **`Gamepad.current` で読んでいる既存のスクリプト**のうち、プレイヤーの移動・狙い・フック・投げるは、読み口（`PlayerInputSource`）を通して席ごとに読めるようにした → `プレイヤーの操作を単体と複数人で切り替える.md`。
  それ以外（`GamepadInput`・`HookAimAssist` など）は、席に関係なく**最後に触ったコントローラ**で動く。
- 1台のキーボードを2人で分ける（P1 は WASD、P2 は矢印）使い方には対応していない。
- `DualDeviceInput`（マウス2台を1人の左手・右手に使う部品）とは別の物。そちらは今回触っていない。
- 席の番号はキーボード・マウスの番号と同じ（席 i ＝ キーボード i 番・マウス i 番）。入れ替えたいときは登録をやり直す。
- 複数のシーンをまたいで使うときは、シーンごとに `InputSeatManager` を置く（起動のたびに保存ファイルを読み込むので、登録は引き継がれる。
  ただしコントローラの割り当ては引き継がれない）。
