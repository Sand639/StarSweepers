## この機能は何か

**離れた場所にいる人と、インターネット越しに一緒に遊べるようにする。**

ホストが**合言葉**を作り、それを相手に伝えると、相手はそれを入れて入ってこられる。
IPアドレスを調べたり、ルーターを設定したりする必要はない。

> **展示では使わない。** 展示会場では `LANでの複数人プレイ.md` のほうを使う。
> これは**家で遊んでもらうため**のもの。

> **2026/10/6 から、宇宙ごみ集めでは「つなぐ画面」はタイトル画面になった**（`タイトル画面.md`）。
> 合言葉（参加コード）で入るほかに、**パブリックの一覧から選ぶ・パスワードを付ける・Steam のフレンドの部屋から入る**こともできる。
> このドキュメントの「つなぎ方の仕組み」（`InternetConnection`・中継サーバー）は、タイトル画面でもそのまま使っている。
> 検証用の `LanPlayTest.unity` などでは、今も左上の仮の接続画面（`LanConnectionUi`）から試せる。

## LANとの違いは「つなぐ前の準備」だけ

**ゲームの中身は、LANのときとまったく同じものが動く。**

| | LAN | インターネット |
| --- | --- | --- |
| つなぎ方 | 相手のIPを直接指定 | **合言葉で中継サーバー経由** |
| **ゲームの中身**（位置・得点・物理の同期） | **同じ** | **同じ** |
| 遅れ | ほぼ無し（〜数ms） | 数十ミリ秒 |
| 使う場面 | **展示会場** | **家庭** |

## なぜ中継サーバーが要るのか

家のPCは**ルーターの内側**にいるため、外から直接つなぐことができない。
つなぐには遊ぶ人全員にルーターの設定（ポート開放）をしてもらう必要があり、現実的ではない。

そこで、**中継サーバーを1つ挟んで、両方から「外向きに」つなぐ。**
これが Unity の **Relay**。Photonのクラウドがやっているのと同じ仕組み。

```
   Aさんの家 ──外向き──→ 中継サーバー ←──外向き── Bさんの家
```

**LANではこの問題自体が無い**ので、中継サーバーを通らない。だから速い。

## 遊ぶ人から見た動き

### 部屋を作る側（ホスト）

1. タイトルで **「インターネットで遊ぶ（離れた人と）」**
2. **「部屋を作る」** を押す（**合言葉が出るまで10〜20秒かかる**）
3. **つながった画面に「■ 合言葉（相手に伝える）」が出る**（例：`ABCDEF`）
4. その合言葉を、相手に伝える（Discordなどで）

> **合言葉は、つながったあともずっと画面に出たまま**にしてある。
> あとから来た人にも伝えられるようにするため。
> **文字を選んでコピーできる**ので、Discordに貼り付けられる。

### 入る側

1. タイトルで **「インターネットで遊ぶ（離れた人と）」**
2. **合言葉を入力**して **「参加する」**

つながると、あとはLANのときと同じ。

## すぐ試す方法

**中継サーバーを通るので、1台のPCで2つ起動しても本当のやりとりが起きる。**
遅れの数字も、そのまま参考になる。

1. `Tools > StarSweepers > アーカイブ > 通信の土台 > LAN検証用のビルドを作る` でビルドする
2. **`2つ起動するだけ.bat`** を実行する
3. 1つ目で「インターネットで遊ぶ」→「**部屋を作る**」→ **合言葉を控える**
4. 2つ目で「インターネットで遊ぶ」→ **合言葉を入力** →「参加する」

### 1台で2つ起動するときの仕組み（何もしなくてよい）

**そのまま2つ起動すると、本来は「すでにこの部屋の一員です」と断られる。**

匿名サインインの身分証は**1台のPCにつき1つ**しか保存されないため、
**両方が「同じ人」として扱われてしまう**のが原因。

そこで、**起動した順に自動で別人扱いになる**ようにしてある。

| 起動 | 扱い |
| --- | --- |
| 1番目 | そのまま（**別々のPCで遊ぶ本番は、全員がここ**） |
| 2番目 | `slot1` として別人扱い |
| 3番目 | `slot2` として別人扱い |

**何も指定しなくてよい。** ログに `このPCで2番目の起動です` と出れば効いている。

> 手で決めたいときだけ、起動時に `-profile ＜名前＞` を付ける。

### 起動引数でも試せる

```
LanPlayTest.exe -nethost              … 部屋を作る（合言葉が画面に出る）
LanPlayTest.exe -netjoin ABCDEF       … その合言葉の部屋に入る
```

### 部屋ができるまで少し待つ

**「部屋を作る」を押してから、合言葉が出るまで10〜20秒かかることがある。**
**中継サーバーの中から一番速い地域を選ぶ測定**（十数か所）を行っているため。
固まったわけではないので、待つこと。

## つながらないときは、ここを見る

| 症状 | 原因として多いもの |
| --- | --- |
| 「Unity Cloud への登録が済んでいません」 | **上の「使う前の準備」がまだ**（登録し直した場合や、`ProjectSettings.asset` のプロジェクトIDが消えた場合）。ここが一番多い |
| 「つなぐ準備に失敗しました」 | インターネットにつながっていない。または Relay が有効になっていない |
| 「部屋に入れませんでした」 | **合言葉が違う**、または**部屋がもう閉じている**（ホストが抜けた） |
| 合言葉を入れたのに反応しない | 大文字と小文字、`0`（ゼロ）と `O`（オー）の間違いが多い |

**ログにも記録が残る。** `[NET]` で始まる行を見れば、どこまで進んで失敗したかが分かる。

## 設定できる値（インスペクターの項目）

シーンの `NetworkManager` を選ぶと出てくる `Internet Connection`。

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| **Max Players** | 同時に遊べる人数。**ホストを含む** | 4 |
| Session Name | 部屋の名前。一覧に出すわけではないので分かりやすければよい | StarSweepers |
| **Is Private** | ONだと部屋の一覧に出さない。**合言葉を知っている人だけが入れる** | ON |
| **Region** | 中継サーバーの地域。**空欄なら一番速い地域を自動で選ぶ**（ふつうは空欄でよい） | 空欄 |

`Lan Connection Logger` 側：

| 項目名 | 意味 | 初期値 |
| --- | --- | --- |
| **Ping Log Seconds** | **遅れをログに残す間隔（秒）。**0にすると残さない | 10 |

> **画面を見られない状況で役に立つ。** 展示当日に「なんか重い」と言われたとき、
> ログを見れば通信のせいかどうかが分かる。

## 仕組み（分かる人向け）

- **Unity公式の Multiplayer Services SDK**（`com.unity.services.multiplayer`）を使っている
- Relay を直接扱うのではなく、その上の **「セッション」** という仕組みを使っている。
  **合言葉の発行と、NGOの開始（ホスト／クライアント）まで自動で行われる**ため
- 流れは次のとおり

  ```
  Unity Cloud の初期化
      ↓
  匿名でサインイン（名前もパスワードも要らない。この場かぎりの身分証）
      ↓
  ホスト：セッションを作る → 合言葉が返ってくる
  参加側：合言葉でセッションに入る
      ↓
  （SDKが NetworkManager を開始する）
      ↓
  あとはLANのときと同じ
  ```

- `Application.cloudProjectId` が空かどうかを**先に見て**、
  登録が済んでいない場合は**分かりやすい日本語で止める**ようにしてある

### なぜ Unity Relay なのか（Steamではなく）

Steamで配布する予定があるため、**Steamの通信を使う案もあった**が、いまは Unity Relay を選んだ。

| | Unity Relay | Steamの通信 |
| --- | --- | --- |
| **NGO 2.13との相性** | **Unity公式なので確実** | 有志製。2.x で動く保証がない |
| 今すぐ試せるか | ○ | **Steamの App ID が要る**（枠を使いたくない） |
| 費用 | 無料枠あり | 無料 |
| 招待のしやすさ | 合言葉を伝える | **フレンドリストから誘える** |

**Steam版を出すときは、Steamの通信も足せる。**
接続部品を差し替えるだけの作りなので、LAN／Relay／Steam の3つを並べて持てる。
詳しくは `Steamでの配布について.md` を読むこと。

## ⏱ 遅れ（ping）の実測値 ← **企画を決めるときに読むこと**

**2026/9/3に、1台のPCで2つ起動して測った結果。**

| | 実測値 |
| --- | --- |
| **純粋な通信の往復**（画面を描かない状態） | **56〜78 ms** ← **これが本当の値に近い** |
| 実際に遊んだとき（1台で2つ描画） | 96〜230 ms（**PCの負荷が乗っている**） |
| つないだ直後・切るとき | 一時的に 400〜650 ms まで上がる |

参考：**LANでは 5〜22 ms** だった。**インターネットにすると、およそ4〜10倍**になる。

### この数字をどう読むか

| 数字 | どう考えるか |
| --- | --- |
| 〜30ms | ほぼ気にならない（**LANはここ**） |
| 30〜80ms | 対戦でも成立する ← **今ここ（56〜78ms）** |
| **80ms〜** | 遅れが分かる。当たり判定の作り方を考える必要がある |

**ぎりぎり「成立する」側だが、上限に近い。**
**判定がシビアな遊び（格闘・シューター）には厳しい数字。**
一方、**レース・陣取り・パーティ**のような「多少ズレても勝敗が壊れない」遊びなら成立する。

> **ジャンルを決めるときの判断材料にすること。**
> 前に「通信のズレに強い遊びを選んでほしい」と伝えたが、**その根拠がこの数字**。

### 測り方の注意

- これは**1台のPCから中継サーバーを往復した値**。実際は遊ぶ人の回線でも変わる
- **展示会場はLANなので、この数字は関係ない**（会場は5〜22ms）
- 数字はログにも残る。`[PING]` で始まる行を見ればよい

### ⚠️ 「1台で2つ起動」だと、数字が悪く出る

**同じ条件で、画面を描く／描かないを比べた結果（2026/9/3）。**

| | 遅れ |
| --- | --- |
| **画面を描かない**（純粋な通信だけ） | **56〜78 ms** |
| **画面を描く**（実際に遊んだとき） | **96〜230 ms** |

**差の40〜150msは、通信ではなくPCの負荷。**
Unityのゲームを2つ同時に描画しているため、片方が処理を待たされている。

**別々のPCで遊べば、この分は乗らない。**
1台で試したときに重く感じても、そのまま本番の重さだと思わないこと。

## 遅れを減らすためにした設定

**「通信の往復（ms）」は縮められないが、「表示するまでの待ち時間」は縮められる。**

| 設定 | 初期値 | 今の値 | 何が変わるか |
| --- | --- | --- | --- |
| **送信回数**（`NetworkManager > TickRate`） | 30回/秒 | **60回/秒** | 位置などが送られる間隔が半分になる |
| **補間の待ち（プレイヤー）** | 0.1秒 | **0.05秒** | **体感に一番効く。**相手の動きの遅れが半分になる |
| 補間の待ち（箱） | 0.1秒 | 0.075秒 | 物理なので、少し長めに残してある |
| 位置の送り方 | 届くまで待ち直す | **届かなければ次で埋める** | 引っかかりが減る |

> **「補間の待ち」とは、相手の動きをなめらかに見せるために、
> わざと少し遅らせて表示する時間のこと。**
> 初期値の0.1秒が、そのまま「相手が遅れて動く」体感になっていた。

**数値は `Assets/Scripts/Network/Editor/LanPlayTestSetup.cs` の先頭にまとめてある。**

> **なめらかさと反応の良さは、片方を取るともう片方が減る関係。**
> カクついて見えるなら待ち時間を長く、もたつくなら短くする。

### この調整の結果（2026/9/3・大槻さん）

- **msの数字はほとんど変わらなかった**（通信の往復時間なので当然）
- **接続してからの反応は少し良くなった**
- 残る重さは**PCの処理能力**によるものと見ている。**別のPCの人と試して確かめる予定**

## できていないこと・既知の問題

- **本当に離れた場所同士で試していない。** 確認したのは1台のPCの中から中継サーバーを
  往復する形。**別々の家からつなぐと、数字も体感も変わる可能性がある**
- **無料枠は「月平均の同時接続50人」「通信量は1人あたり3GiB・月150GiBまで」**（2026/9/14にAIが公式の料金ページで確認。変わることがある）。
  身内や展示の数人規模では届かない見込み。**広く配るときは見直すこと。** 使用量は Unity Cloud の Relay の画面の **Usage** で見られるはず
- **3人以上での接続を試していない。** 確認できたのは2人まで
- **部屋の一覧・マッチング機能は無い。** 合言葉を知っている人しか入れない
  （知らない人と当たらないので、身内で遊ぶ分にはこのほうが安全）
- **ホストが抜けると全員が遊べなくなる。** 部屋ごと消えるため。
  再接続の作りは入れていない（`ネットワークの制作工程.md` の工程5で扱う）
- **ズルへの対策は、移動だけ残っている。** 得点と物理はホストが決めているが、
  位置は本人が申告する。**LANの身内プレイでは問題にしなかったが、
  インターネットで不特定多数に配るなら、いずれ見直す必要がある**
