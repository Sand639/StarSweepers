## この機能は何か

`PullAblePlate` をオンライン対戦でも全員の画面で同じ場所へ動かす機能。

現在は、引っ張った Player のPCだけが移動床を動かしている。そのため、ホストやほかの参加者の画面では床が元の場所に残る。この設計では、参加者からの引っ張りをホストへ伝え、**ホストだけが衝突と移動先を決めたあと、その位置を全員へ配る**。

既存の `PushableBox` と同じ「参加者はホストへ依頼し、ホストが物を動かす」方式を使う。床上の Player は `SpaceJunkRotatingFloor` と同じく、**各PCが自分の Player だけを運ぶ**。

---

## 遊ぶ人から見た動き

| 操作・状況 | 結果 |
| --- | --- |
| ホストが柱または場外 Anchor を引っ張る | ホストが衝突を確認して床を動かし、全員の画面へ同じ位置を配る |
| 参加者が柱または場外 Anchor を引っ張る | ホストへ移動を依頼し、ホストが採用したあと全員の床が動く |
| 2人がほぼ同時に引っ張る | ホストが先に受け付けた1件だけを実行し、移動中の依頼は採用しない |
| 移動先に固定床または別の移動床がある | ホストの物理判定で衝突面の直前に止まり、その結果が全員へ配られる |
| Player が移動床に乗っている | 各PCが自分で操作している Player だけを床の移動量に合わせて運ぶ |
| 1人用で遊ぶ | 通信を使わず、現在と同じ本機だけの処理で動く |

参加者側で先に床を動かす予測処理は行わない。通信の往復ぶんだけ開始が遅れる可能性はあるが、各PCで床の位置が分かれることを防ぐ。

---

## 採用する方式

### 採用：ホスト権限＋NetworkTransform

- 参加者は `ServerRpc(RequireOwnership = false)` で移動方向または場外 Anchor の位置を送る。
- ホストだけが `Rigidbody.SweepTestAll` と `Rigidbody.MovePosition` を実行する。
- Server 権限の `NetworkTransform` が位置を全員へ同期する。
- `IsMoving` はホストが書き込む `NetworkVariable<bool>` で全員へ同期する。
- Player の追従は各PCが自分の Owner Player だけに適用する。

この方式は `PushableBox` のホスト物理と、`SpaceJunkRotatingFloor` の Owner Player 追従を組み合わせたもの。

### 採用しない方式

| 方式 | 採用しない理由 |
| --- | --- |
| 引っ張った人へ床の Ownership を渡す | 同時操作で Ownership の奪い合いが起き、衝突判定を誰が決めるかが不安定になる |
| 全PCで同じ移動を計算する | 入力が届く時刻と物理状態がPCごとに違うため、衝突位置が少しずつずれる |
| ServerTime だけから床位置を計算する | 列車や回転床と違って操作時刻・方向・衝突結果が毎回変わるため、位置の再現に必要な状態が増えすぎる |

## 部品と責任

### `PullAblePlate`

- `MonoBehaviour` から `NetworkBehaviour` へ変更する。
- `NetworkObject` を必須部品にする。
- 通信が開始されていない時は現在の `StartMove` をそのまま使う。
- 通信中のホストは自分で `StartMove` を呼ぶ。
- 通信中の参加者は `ServerRpc` を呼び、自分のPCでは床を動かさない。
- サーバーが移動中の時は新しい依頼を拒否する。
- 移動開始・衝突停止・通常終了・無効化のすべてで、同期する移動中状態を正しく戻す。

### `NetworkObject`／`NetworkTransform`

- Root に置く。
- `NetworkTransform` は Server 権限に固定する。
- 位置を同期する。現在のゲームでは床は水平移動だけで回転・大きさを変更しないため、実装時に不要な同期項目を止められるか確認する。
- Prefab の `NetworkObject.GlobalObjectIdHash` が0でも、それ自体は正常とする。
- `STAGE_05` を保存し直し、Scene 上の各 Plate instance に固有で0ではない `GlobalObjectIdHash` と、Prefabを示す `InScenePlacedSourceGlobalObjectIdHash` を付ける。
- `STAGE_05` 上の Plate が Network Scene Object として有効になることを Unity の検査と実機接続で確認する。

### Player追従

- 通信していない時は、現在と同じく登録された全 Passenger を動かす。
- 通信中は、Passenger の `NetworkObject` を確認する。
- `IsSpawned && !IsOwner` の Player はそのPCでは動かさない。
- 自分が Owner の Player、または NetworkObject を持たない1人用 Player だけを動かす。
- NetworkTransform で受け取った床の前回位置と現在位置の差を使い、参加者側でも自分の Player を運ぶ。
- ホスト側で直接加えた移動量と、観測した床の差分を二重に加えない。

## 処理の流れ

### 柱から引っ張る

1. Player が `PullAblePlatePullPoint` のゲージを完成させる。
2. `PullAblePlate.Pull(direction)` を呼ぶ。
3. 1人用ならその場で移動する。
4. ホストならその場で移動を開始する。
5. 参加者なら方向を ServerRpc で送る。
6. ホストが移動中でないことと方向が有効なことを確認する。
7. ホストが衝突を調べながら移動する。
8. NetworkTransform が位置を全員へ配る。

### 場外 Anchor から引っ張る

1. Player が `PullAblePlateAnchor` のゲージを完成させる。
2. 既存処理が Player の乗っている Plate を選ぶ。
3. `PullToward(anchorPosition)` を呼ぶ。
4. 参加者の場合は Anchor のワールド位置をホストへ送る。
5. ホストが現在の Plate 中心から Anchor までの水平方向を計算して移動する。

### Playerを運ぶ

1. 各PCの `PassengerArea` が、そのPCで有効な Player を登録する。
2. Plate の位置が変わったら、前フレームとの差分を求める。
3. 通信中はそのPCが Owner の Player だけへ差分を加える。
4. Player 自身の NetworkTransform が、動いたPlayer位置をほかのPCへ配る。

---

## 不正・重複した依頼の扱い

- 移動中に届いた依頼は無視する。
- 長さがほぼ0の方向、無効にした柱の方向、移動距離が0以下の場合は開始しない。
- 参加者が送った現在位置を床の正解として使わない。正解の位置と衝突判定は常にホストが持つ。
- 同じフレームに複数の依頼が届いた場合は、ホストが先に処理した1件だけを採用する。
- RPCが届かなかった場合に自動再送する独自処理は追加しない。Netcode の信頼性設定に任せる。

## テストと確認

### 自動テスト

- `PullAblePlate` が `NetworkBehaviour` であり、`NetworkObject` を必須とする。
- prefab Root に `NetworkObject` と `NetworkTransform` がある。
- `NetworkTransform` が Server 権限になっている。
- `STAGE_05` の Plate instance に0ではない固有の `GlobalObjectIdHash` がある。
- Offline の既存移動、連続拉扯、衝突停止、反対方向への離脱が変わらない。
- Passenger の判定で、通信中の非Owner Playerを動かさず、Owner Playerだけを動かす。
- 移動中状態の開始・終了・中断が戻る。

### Unityでの接続確認

- Host と Client の2台で同じ Stage を開く。
- Host が柱を引き、両方の画面で同じ位置へ動くことを確認する。
- Client が柱を引き、両方の画面で同じ位置へ動くことを確認する。
- Host と Client が同時に別方向へ引き、1回分だけ動くことを確認する。
- Host／Client がそれぞれ床に乗った状態で動かし、自分の Player が床と一緒に動くことを確認する。
- 固定床と別 Plate に衝突した時、両方の画面で同じ位置に止まることを確認する。
- 場外 Anchor でも同じ確認を行う。

## できていないこと・既知の問題

- コード、Prefab、`STAGE_05` のScene ID、通信Prefab登録までは反映済み。Unity 6000.3.14f1のEditModeテストは67件すべて成功した。
- 自動テストでは複数PC間の通信そのものまでは再現できない。HostとClientを実際につなぎ、床位置、Player追従、衝突停止、同時操作、連続操作を確認する必要がある。
- 通信遅延を隠す Client 予測は今回追加しない。
- `MovableBlock` のオンライン同期は今回の対象外。
