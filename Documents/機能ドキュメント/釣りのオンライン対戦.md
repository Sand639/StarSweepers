## この機能は何か

**釣りフックの遊びを、離れた人と最大8人で対戦できるようにした。**

すでにある通信の土台（合言葉でつなぐ仕組み）を**ロビー（待合室）**として使い、
人数がそろったらホストがボタンを押して、**全員がまとめて釣り会場のシーンへ移動する。**

**2人1組のチーム戦。** 集めた物資を自分たちのゴールへ投げ入れて点を取り合う。

> つなぎ方そのものは `インターネットでの複数人プレイ.md` と同じ（変えていない）。
> こちらは**つないだあとの遊び**を足したもの。

---

## 遊ぶ人から見た流れ

1. `FishingLobby.unity` を開いて再生する
2. **「インターネットで遊ぶ（離れた人と）」→「部屋を作る」**（合言葉が出るまで10〜20秒）
3. 合言葉を相手に伝えて入ってもらう（**最大8人**）
4. ロビー画面に、入っている人と**チーム分け・ゴールの割り当て**が出る
5. ホストが**マップを選び**（`FishingOnline` か、`FishingMap〜` のマップ。詳しくは `釣りのマップ作りとマップ選び.md`）、**ホストだけに出ている「ゲーム開始」**を押す
6. **全員のシーンがまとめて、選んだマップへ切り替わる**
7. 物資を釣って、自分たちのゴールへ投げ入れる

操作は1人用と同じ（WASD移動／マウスで向き／左クリックでチャージ・発射・スキルチェック）。

## チーム分けとゴール

**2人1組のチーム。ゴールはステージの四方に常に4つ。**

| 人数 | チーム数 | ゴール4つの割り当て |
| --- | --- | --- |
| 1〜2人 | 1 | 4つすべてそのチーム |
| 3〜4人 | 2 | **各チーム2つずつ** |
| 5〜6人 | 3 | 各チーム1つずつ ＋ **どのチームでも入る共通ゴール1つ** |
| 7〜8人 | 4 | **各チーム1つずつ** |

**人が入ったり抜けたりすると、チーム数とゴールの割り当ては自動で組み直される。**
ゴールの床は、持ち主のチームの色に塗られる。

### 点の入り方

| ゴールの種類 | 誰の点になるか |
| --- | --- |
| **チームのゴール** | **そのゴールを持つチーム**（誰が投げ入れても、そのチームの点） |
| **共通ゴール**（5〜6人のときの1つ） | **投げ入れた人のチーム** |

つまりチームのゴールは「自分たちの陣地へ運ぶ」形になり、
**間違えて相手のゴールへ入れると、相手に点が入る。**

> **このルールは `Assets/Scripts/Fishing/FishingTeams.cs` に1か所でまとまっている。**
> バランスを変えたいときは、そのファイルだけ直せばよい。

## 試合の決着（制限時間）

**初期設定は「制限時間 3分」。** 時間切れの時点で点が多いチームの勝ち（同点なら引き分け）。

| 場面 | 画面 |
| --- | --- |
| 対戦中 | 画面上に**残り時間**（`0:00` 形式）。**残り30秒を切ると赤くなる** |
| 決着後 | 画面中央に**勝ったチーム**と、チームごとの最終得点 |
| 決着後 | **ホストだけに「ロビーへ戻る」**が出る。押すと全員がロビーへ戻り、点数はリセットされる |

**決着後は、移動もフックも受け付けなくなる**（結果を見る時間になる）。

### 目標点に切り替えるには

`FishingMatch` の **End Rule** を `TargetScore` に変えるだけ。
そのときは残り時間の代わりに「◯点先取」と出て、**先に目標点に届いたチームの勝ち**になる。

> **決着の判定は `FishingMatch.CheckMatchEnd()` の1か所だけ。**
> 「制限時間か目標点か、今後変わるかもしれない」という話だったので、
> **どちらにも差し替えられる形**にしてある。条件を増やすときもここに足す。

## 誰が何を決めているか（一番大事なところ）

`ネットワークの制作工程.md` の推奨（**動きは本人、勝敗と点数はホスト**）に合わせている。

| 場面 | 決める人 | 理由 |
| --- | --- | --- |
| **残り時間と決着** | **ホスト** | 全員で同期された時計（`ServerTime`）を使うので、どのPCでも同じ残り時間になる |
| 走る・向きを変える | **本人** | 操作が軽くなる |
| **物資を引き寄せている間の動き** | **引っ掛けた本人** | ゲージと物資の動きがずれると、スキルチェックが成立しない |
| **同じ物資を二人が引っ掛けたとき** | **ホスト** | 早い者勝ちをホストが決める。負けた人にはフックが戻る |
| **投げたあとの飛び方** | **ホスト** | どこへ落ちたかを全員で一致させる必要がある |
| **ゴールに入ったかの判定と点数** | **ホスト** | それぞれが数えると、同じ物資で何度も点が入る |
| 爆発物の導火線に火がつくこと | **ホスト** | 本人だけで火をつけると、他の人には突然爆発したように見える |
| 爆発の被害（物資が消える・スタン） | **各PC** | 位置が同期されているので、どのPCでも同じ結果になる。**自分がスタンするかは自分のPCが決める**ので、操作が止まるまでの遅れが無い |

引き寄せの間だけ、**その物資の「持ち主」を引っ掛けた人へ移している**（`ChangeOwnership`）。
だから既存の `ThrowController` がそのまま引き寄せを動かせて、それが全員に配られる。
投げるとホストが持ち主を取り戻し、力を加える。

## シーンの作り方

1. Unityで、スクリプトのコンパイルが通るのを待つ（Consoleに赤エラーが無いこと）。
2. メニュー **`Tools > StarSweepers > 釣りのオンライン用シーンを作る（ロビー＋会場）`** を実行。
3. Console に「【オンライン】ロビーと釣り会場のシーンを作りました。」が出れば成功。
4. `FishingLobby.unity` を開いて再生。

### ⚠ Build Settings への登録について

**Netcode で「ホストが押したら全員のシーンが切り替わる」を使うには、
そのシーンが `File > Build Settings` のシーン一覧に入っている必要がある。**
入っていないと「シーンを読み込めませんでした」で止まる。

ツールが**自動で2つのシーンを登録する。**

> これは「**検証用シーンはビルドに入れない**」という決まり（`シーンとプレハブの作り方.md`）と
> ぶつかるが、**プロトタイプの間はそのまま検証用シーンとして入れてよい**との回答をもらっている
> （2026/9/10・小野田さん）。**本番のビルドを作る段階で、あらためて整理すること。**

## 1台のPCで4人プレイを試す方法

**エディタの再生では1人分しか動かない。** `.exe` を作って4つ同時に起動する。

> ⚠ **`LAN検証用のビルドを作る`（`LanTestBuilder`）は使わない。**
> あちらは `LanPlayTest.unity` だけをビルドするので、**釣りのシーンが入っていない。**
> 釣り用は下の専用ツールを使うこと。

1. `Tools > StarSweepers > 釣りのオンライン用シーンを作る（ロビー＋会場）` … シーンを作る（1回でよい）
2. **`Tools > StarSweepers > 釣りのオンライン検証用のビルドを作る`** … `.exe` を作る
   - 出力先は `StarSweepers/Build/FishingOnlineTest/`（Gitには入らない）
3. できたフォルダの `.bat` を実行する

| ファイル | 何をするか |
| --- | --- |
| **`4人で自動接続.bat`** | **これが一番速い。** 4つ起動して、そのまま4人でつながる（**合言葉は要らない**）。あとはホストの窓で「ゲーム開始」を押すだけ |
| `4つ起動するだけ.bat` | 4つ起動するだけ。**本番と同じ手順**（合言葉）を試すとき |
| `2つ起動するだけ.bat` | 2人でさっと確かめたいとき |

`4人で自動接続.bat` は**LANの折り返し接続（127.0.0.1）**を使う。
合言葉のやりとりが要らないので、遊びの中身を確かめるのに向いている。
**インターネット越しの動き（遅れ）を確かめたいときは `4つ起動するだけ.bat`** で合言葉を使うこと。

> **窓は 960×540 で開く**（1920×1080 の画面にちょうど2×2で並ぶ大きさ）。位置は手で並べること。
> 画面がこれより小さい場合は `.bat` の中の数字を書き換えてよい。
> **UIは窓の大きさに合わせて自動で縮む**ので、小さくしてもボタンが押せなくなることはない。
> **枠（接続・通信の様子・ロビー）は、上の帯をつかんでドラッグすると動かせる。**
> 帯の右端の「-」で折りたためる（「+」で開く）。重なって読めないときは動かすか畳むこと。
> **キーボードとマウスは、いま選んでいる窓にしか届かない。** 4つの窓を順にクリックして、1人ずつ動かして確かめる。
> 1台で複数起動しても「同じ人」と扱われない仕組みは、ゲーム側が起動順で自動的に分けてくれる
> （`インターネットでの複数人プレイ.md`）。**`.bat` 側で何かを指定する必要はない。**

### 4人だと2チーム（2vs2）になる

4人でつながると、ロビーに「**2チームに分かれます**」と出て、
ゴールは**各チーム2つずつ**に割り当てられる。ロビーの画面で確認できる。

## 「ゲーム開始」を押しても移行しないとき

**原因のほとんどは、シーンがビルドの一覧に入っていないこと。**
Netcode でシーンをまとめて切り替えるには、**そのシーンが `File > Build Settings` の
シーン一覧に入っている必要がある**（エディタでもこの一覧が使われる）。

いまは、押す前に自動で確かめて、入っていなければ**ロビーの画面にその旨を出す**ようにしてある。

| 画面に出る文 | どうするか |
| --- | --- |
| 「シーン『FishingOnline』がビルドの一覧に入っていません」 | `釣りのオンライン用シーンを作る` を**実行し直す**（自動で登録される）。または Build Settings に手で追加 |
| 「Enable Scene Management が OFF です」 | `NetworkManager` の同項目をONにする |
| 「シーンを読み込めませんでした（SceneEventInProgress）」 | 前のシーン切り替えが終わっていない。少し待って押し直す |
| **ボタンが見当たらない** | 窓が小さすぎてUIが画面外に出ていた（**2026/9/10に修正済み**）。UIは窓に合わせて縮み、**「ゲーム開始」はパネルの一番上**に出る。**枠が他の表示に隠れているときは、帯をドラッグして動かす**か、上に重なっている枠を「-」で畳む |

Console にも `[FISH]` で始まる行が出る。成功すると
`[FISH] シーン「FishingOnline」へ全員で移動します。` が出る。

## 設定できる値（インスペクターの項目）

### 釣り会場のシーン（`FishingMatch` を選ぶ）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| **End Rule** | 決着のつけ方（`TimeLimit` ／ `TargetScore`） | TimeLimit |
| **Time Limit Seconds** | 制限時間（秒） | 180（3分） |
| Target Score | 目標点（End Rule が TargetScore のとき） | 10 |

`FishingHUD` の `Fishing Match UI` 側：

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Lobby Scene Name | 「ロビーへ戻る」で移動するシーン名 | FishingLobby |
| Warn Seconds | 残り時間を赤くし始める秒数 | 30 |

### ロビーのシーン（`NetworkManager` を選ぶ）

| 項目名 | 意味 | 実装したときの初期値（目安。調整で変わる） |
| --- | --- | --- |
| Internet Connection > **Max Players** | 同時に遊べる人数（ホストを含む） | **8** |
| Fishing Lobby UI > **Game Scene Name** | 最初に選ばれているマップのシーン名 | FishingOnline |
| Fishing Lobby UI > Map Scene Prefix | この名前で始まるシーンを、マップの候補として並べる | FishingMap |
| NetworkManager > **Enable Scene Management** | **ONでないとシーンを切り替えられない** | ON |
| NetworkManager > Tick Rate | 1秒に何回位置などを送るか | 60 |

### 釣り会場のシーン

物資・爆発物・スキルチェックの数値は1人用と同じ（`釣りフックの操作.md` を参照）。

**物資と爆発物は、ホストのスポナーが次々に降らせる**（`FishingObjectSpawner`。割合・上限は `釣りの物資のスポナー.md`）。

## できていないこと・既知の問題

- **⚠ まだ一度もコンパイル・実行していない。** 実装しただけの状態。
  最初の実行でエラーが出る可能性が高いので、Console を見ながら直す前提。
- **結果画面からロビーへ戻ると、点数はリセットされる**（試合の記録は残らない）。
- **時間切れの瞬間に飛んでいる物資は、点にならない**（判定が間に合わない）。
- **参加番号は、空いている一番小さい番号が割り当てられる**（2026/9/24 から）。
  途中で誰かが抜けても、次に入ってきた人が**すでにいる人と同じ番号になることはない**。
  ただし釣りでは番号でチームが決まるので、**抜けた人の番号を引き継ぐと、その人のチームに入る**。
- **チーム分けを手で変えられない。** 入った順に2人ずつ組まれる。
- **引き寄せ中の物資は、他の人からは少し遅れて見える**（通信の遅れのぶん）。
  引っ掛けた本人の画面では遅れない。
- **3人・5人・7人のような奇数だと、1人だけのチームができる。**
- **ホストが抜けると全員が遊べなくなる**（既存の通信の作りと同じ制限）。
- **爆発の被害を各PCが計算している。** 位置が大きくずれていると、
  片方の画面だけスタンする可能性がある（遅れが小さければ起きない想定）。
- オンライン用プレイヤーの見た目は基本形状のカプセル。
  `PlayerRig.prefab` を使っていないのは、中に一人称/三人称の操作とカメラが入っていて、
  **プレハブとして持つと毎回それを取り除く処理が必要になる**ため。
