## この機能は何か

**ラウンドが始まるときの演出。** 前はマップに着いた瞬間に始まっていたが、演出を見せてからカウントダウンで始まるようにした。

演出は2種類あり、マップに置いた進行役（`SpaceJunkRound`）の **Intro Style** で切り替える。

| Intro Style | 中身 | いま |
| --- | --- | --- |
| **GoalFlyIn** | **ゴールエリアがプレイヤーを乗せて飛んできて、元の位置に設置される**（2026/10/27〜） | **使っている** |
| CameraTour | カメラがマップを回って見せる（2026/10/7〜10/26） | 使っていない（大槻さん「また使うかもしれないから無効化だけしておいて」） |

### いまの流れ（GoalFlyIn。2026/10/27〜）

| 順番 | 何が起きるか | 長さ（初期値） |
| --- | --- | --- |
| ⓪ 読み込み待ち | 全員の読み込みを待つ。ゴールエリアは奥の飛び始めの位置で止まっている。真ん中に**マップの名前**と「**ラウンド ○**」 | 1.5 秒 |
| ① 飛んでくる | 各チームのゴールエリアが、**そのチームのプレイヤーを乗せて、横に並んでマップの奥から手前へ**飛んでくる。カメラは**ゴールエリア全部の中心を狙い、全部が映るように**ズームを変える。**名前のタグを1人ずつ順に強調する**（下の説明） | 3 秒（＝A 秒） |
| ② 設置 | マップに近づいたら、それぞれ**元のゴールの位置へ飛んで設置される**。カメラはふだんのカメラ（全体カメラ）へ移る | 1.5 秒 |
| ③ カウントダウン | **設置されたら** 3・2・1 → 「**START!**」を 1 秒。**START から動ける** | 3 秒 |

- 「奥」は北（ふだんのカメラの画面の奥）。ゴールエリアはマップの北の端の少し先まで飛んできて、そこから東西（4チームなら四方）の元の位置へ分かれて降りる
- ① の間、ゴールエリアは**乗っている人の並びがカメラから見て左右になるように**向きを回している（東西のゴールは前後に並ぶ形なので、そのままだと重なって見えるため）。② で元の向きに戻る
- **名前のタグの強調**：① の秒数（A 秒）÷ 乗っている人数 ごとに、**カメラから見て左の人から順に1人ずつ**、名前のタグが拡大と縮小をくり返す（初期値は 1.8 倍まで、2 回）。4人なら 0.75 秒ずつ
- プレイヤーは**ゴールエリアの上の決まった場所**に乗っている。設置されると、そのまま**ゴールエリアの上に立った状態**で始まる（出てくる場所の決め方は下の「プレイヤーが立つ場所」）
- 閉ざされたゴール（3チームのときに余るゴール）は飛ばない
- ⓪〜START の間は**誰も動けず、素材・爆弾・隕石も出ない**
- **残り時間とイベント（お題セットなど）は START から数える**（演出のぶん減らない）。演出中は、決めた制限時間（60秒なら 60）のまま止まって見える
- **時間は全員で同期された時計で決めている**ので、どのPCでも同じタイミングで START になる

> ゴールエリアは後から1つの3Dモデルに替える予定（大槻さん）。替えたら、ゴールの `SpaceJunkGoal` の **Intro Visual** にそのモデルを入れれば、モデルごと飛ぶ（下の「設定できる値」）。

### プレイヤーが立つ場所（2026/10/27〜）

ラウンドの始まり・`R` で戻る・落ちて戻る、のどれでも同じ場所に出る（`SpaceJunkPlayerSetup`）。

| Spawn On Goal Area | 出てくる場所 |
| --- | --- |
| **ON（初期値）** | **自分のゴールエリアの上**。ゴールから見て横に、**ゴールエリアの幅をチームの人数で等分した場所**に並ぶ（幅 5m に2人なら 2.5m 間隔。並び順はロビーで入った順） |
| OFF | ゴールから 4m 内側に、2m 間隔の横一列（2026/10/27 の朝に作った形。大槻さん「さっき作ってもらったのも一応残しておいて」） |

- ゴールエリアに床が無いマップ（ゴールが床の外にあるマップ）では、ON でも横一列になる（落ち続けないように）
- 1チームで全部のゴールが自分たちのものなら、番号がいちばん小さいゴールに乗る

### 前の演出（CameraTour。2026/10/20〜10/26）

Intro Style を CameraTour にすると、この流れに戻る。

| 順番 | 何が起きるか | 長さ（初期値） |
| --- | --- | --- |
| ⓪ 読み込み待ち | 全員の読み込みを待つ。カメラは ① の回り始めの位置で止まったまま。真ん中に**マップの名前**と「**ラウンド ○**」 | 1.5 秒 |
| ① マップの紹介 | **マップの中央（0,0,0）を向いたまま**、真上（Y軸）から **45度** 傾けた所を、中央を中心に **180度** 回る。最後に自分のチームの側に来る | 3 秒 |
| ② 自分のチームに寄る | 自分のチームの後ろ（マップの外側、少し上）へ寄る。距離は 8（前は 6） | 1 秒 |
| ③ 止まる | ② の位置で止まる | 0.5 秒 |
| ④ チームの周りを回る | ② の位置から、チームの中央を中心に **-120度** 回りながら（マイナスは逆向き）、**少しずつ離れて上がり、最後は上からチームを映す**（距離 8→10、高さ 3.5→10） | 1.5 秒 |
| ⑤ 止まる | 回り終わった位置で止まる | 1 秒 |
| ⑥ 全体カメラへ移る | ふだんのカメラ（全体カメラ）の位置へ移る | 1 秒 |

文字は、⓪〜① にマップの名前・「ラウンド ○」、④ が始まって **1 秒** たったら「3」「2」「1」（3 秒）、終わったら「START!」を 1 秒（ここから動ける）。初期値では、⑥ が終わって全体カメラになった 0.5 秒あとに START になる。
「チームの中央」は、自分と同じチームのプレイヤー全員の位置の平均。列車・回転する床・ベルトコンベアは演出中も動いている。

### もっと前の流れ（2026/10/7〜10/19。参考）

マップの上をぐるっと160度回る（4秒）→ 自分のプレイヤーの後ろへ寄る（1.5秒）→ 3・2・1 → START! と同時に動けるようになり、0.7秒でふだんのカメラへ戻る。マップの中央はゴールの位置の平均から求めていた。

## 設定できる値

**いろいろ試すために、秒数・向き・高さはインスペクターで変えられる。** 進行役はプレハブなので、**`Assets/Prefabs/SpaceJunk/Online/SpaceJunkRound.prefab` を開いて変えれば、全マップに効く**（各マップの Hierarchy の「SpaceJunkRound」は、このプレハブを置いたもの）。
ラウンドごとにマップのシーンを読み込み直すので、**再生中に変えた値は次のラウンドで元に戻る。** 試すときは再生を止めてからプレハブで変えて保存する。シーンの Hierarchy から変えると**そのマップだけの上書き**になる（太字で表示される）ので注意。

> 2026/10/27 に足した項目（Intro Style・ゴールが飛んでくる演出の項目）は、プレハブにはまだ保存されていない（コードの初期値が使われる）。プレハブを開いて保存すると書き込まれる。

## 仕組み（分かる人向け）

- `SpaceJunkRound` に `playStartServerTime`（NetworkVariable）がある。ホストが開始時に「いま＋待ち＋演出の長さ」を入れる。演出の長さは、GoalFlyIn なら「① ＋ ② ＋ カウントダウン」、CameraTour なら「①＋②＋③＋カウントダウンまでの待ち＋カウントダウン」。`endServerTime` とイベントの開始時刻もここから数える
- 演出の各段階の切れ目は、`IntroStartServerTime`（＝ `playStartServerTime` − 演出の長さ）からの経過時間で決める。設定の秒数は、どのPCも同じシーンの値を使うので一致する
- `IsIntro` ＝ Playing 中で、まだ `playStartServerTime` より前。`IsPlaying` は演出中 false なので、`PlayAllowed` を見ているもの（スポナー・爆弾・隕石・操作）は全部止まる
- 演出が終わった瞬間（`IsIntro` が true → false）に、全員のPCで自分の操作を戻す
- カメラは**ふだんのカメラとは別のカメラ**（`RoundIntroCamera`、深さを上げて重ねる）を一時的に作って動かす。ふだんのカメラの動きには手を出さない
- **GoalFlyIn のゴールエリアとプレイヤー**
  - ゴールエリアの位置は、全員のPCが同じ時計・同じ設定から同じ計算をするので、通信で送っていない
  - 飛んでいるのは `IntroVisual` の MeshRenderer を写した物（当たり判定なし）。本物は動かさず、Renderer を切って隠す（本物を動かすと、ボットの歩ける床の地図やゴールの判定がずれる）。設置したら写しを消して本物を出す
  - プレイヤーは、設置されたときに立つ場所（`SpaceJunkPlayerSetup.TryGetGoalSpawnPosition`。ばらけさせないので他人のぶんも求められる）を、ゴールエリアと同じだけ動かして回した所に、**全員のPCで全員ぶん**置く。乗っている間は CharacterController を切る（他人のぶんは元から切れている）
  - 自分のぶんは、その位置が通信（NetworkTransform）で配られる。他人のぶんは、通信の遅れでゴールエリアからずれて見えないよう、こちらで上書きする。**NetworkTransform は PreLateUpdate で位置を入れるので、`DefaultExecutionOrder(10000)` の LateUpdate で上書きすれば、そのフレームの表示に勝てる**
  - 名前のタグは `SpaceJunkGoalFlyIntro.ViewCamera`（演出のカメラ）があればそちらを向き、`NameEmphasisOf` の倍率で大きくなる
  - ② のカメラは、① の終わりの見え方から、ふだんのカメラへまっすぐ移す。**② のゴールエリアを追うと、ゴールエリアがカメラの真下や後ろへ回り込み、カメラが振り返って移る途中で斜めを向いた**（画像で確かめて直した）
- チームは `SpaceJunkSession.TeamOf(人ごとの番号)` で見る

## できていないこと・既知の問題

- **人の目で、エディタやビルドで見る確認はまだ**（Unity を画面なしで動かし、演出の途中を画像に撮って確かめた。STAGE_01・ボット3体の2対2だけ。文字（3・2・1）は画像に写らないので見ていない）
- 3チーム・4チーム、1チームのときは試していない
- 4人のチームだと、ゴールエリアの幅（5m）を4等分して 1.25m 間隔になり、名前が長いと名前のタグが重なる
- 自陣カメラ（ふだんのカメラが自分を追う種類）にしているときは、② でふだんのカメラへ移る間、ふだんのカメラが飛んでいる自分を追って動いている。全体カメラ（最初の種類）では起きない
- 「全体カメラへ移る」は、正確には「**いまのステージのカメラ**へ戻る」。演出中に C キーで切り替えると、切り替えたカメラへ戻る
- 文字はコードで作っている（プレハブではない）。見た目を凝りたくなったらプレハブにする
- ラウンドの最中に入ってきた人には演出は出ない（すでに START 後のため）
