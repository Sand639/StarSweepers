## この機能は何か

ゲームの本番で使う**新しいプレイヤー**。小野田さんが書き起こした仕様（見た目：キャラモデル・キャラリング・ネーム／操作：移動・狙う・引っ張る・クリティカルプル）をもとに作った。

- 体は**キャラクターダミー**（Hansさん作の仮モデル `SM_Character_Dummy.fbx`。2026/10/29 にカプセルから差し替え。アニメーションはまだ無い）
- 足元に**チームの色のリング**。形は 円・三角・四角・星・六角形 から選べる
- 頭の上に**名前**（チームの色）
- RT／左クリックの長押しで**届く長さが矢印の帯で出て**、離すと**光線が伸びる**
- 光線が物資に当たると、物資を**床に置いたまま 1.5 秒で引き寄せる**。途中で押すと**頭を越えて後ろへ**、押さなければ**前へ**投げる
- 物資のまわりの合図に合わせて押すと**クリティカルプル**（もっと高く遠くへ飛ぶ）

**今の宇宙ごみ・釣りのプレイヤー（`SpaceJunkPlayer` / `FishingOnlinePlayer`）とは別に作ってあり、そちらは何も変えていない。**
宇宙ごみのオンライン（タイトル → ロビー → マップ）では、**人のプレイヤーはいつもこの体で出る**（2026/11/3 から。下の「宇宙ごみのオンラインで遊ぶ」）。
今の体（フック）のプレハブとコードは消していないが、人のプレイヤーには使わない（ボットだけが使う）。

## 遊ぶ人から見た動き

| 操作（コントローラー／キーボード・マウス） | 結果 |
| --- | --- |
| 左スティック／WASD | 歩く。体は**歩いている方向**を向く |
| 右スティック／マウス | 狙う方向を変える。マウスは**プレイヤーを中心にした半径1mの円の中だけ**を動く小さな円（カーソル）で、Windows のカーソルは隠れる |
| RT／左クリックを押す | 狙い始める。リングの縁から、**届く長さの矢印の帯**が出る。体は狙う方向を向く。**歩ける** |
| 押している間 | 帯が最短から最長まで伸びていく |
| 離す | 光線がその長さまで伸びる。**ここから投げ終わるまで歩けない**（向きは変えられる） |
| 光線が物資に当たる | 自動で引き寄せ始める。物資は床の上を引きずられ、**距離に関係なく 1.5 秒で**手前に着く |
| 引き寄せの途中で向きを変える | **光線が釣り糸のようにしなる**（2026/11/4）。手元からは体の向きに少し遅れて出て（行き過ぎてからビヨンと戻る）、曲がって物資へつながる。物資は**しなった光線に沿って、プレイヤーのまわりを前の側へ回り込む**。着く時間（1.5 秒）は変わらない。向きを変えなければ今までどおりまっすぐ |
| 引き寄せの途中で RT／左クリック | **後ろへ投げる。** 押した瞬間の位置から、頭を越える放物線で後ろへ飛ぶ。**回り込んでいる途中なら、回っている勢いを残して斜め後ろへ飛ぶ**（2026/11/4。どれだけ勢いに寄せるかは Throw Follow Motion） |
| 縮んでくる輪が物資のふちに重なった瞬間（フチが金色にくっきり光る間）に押す | **クリティカルプル。** 物資が白く光って一瞬止まり、星のかけらが飛び散る。物資の向こう側から輪が噴き出して（推進の衝撃波）、もっと高く遠くへ飛ぶ |
| 最後まで押さない | 手前に着いたところで、**向いている方向（前）へ**床すれすれに投げる |
| 何にも当たらない・壁に当たる | 光線が戻ってくる。戻りきったら歩ける |

- クリティカルの合図は**物資のまわりにだけ出す**（ゲージなどの画面の表示は出さない）。押すのは1回だけで、それで決まる（連打で当てられない）
- 合図は**受付が始まる 0.5 秒前から**出る（2026/11/4）。受付は 0.2 秒しかなく、光ったのを見てから押すのでは間に合わないため。下の「クリティカルの仮のエフェクト」
- 狙っていないときは、体は歩いている方向を向く

### 検証シーンでの試し方

1. Unity のメニュー `Tools > StarSweepers > プレイヤー（本実装）の検証シーンを作り直す` を押す（`Assets/Scenes/Test/SweeperPlayerTest.unity` が開く）
2. 再生する。左上に操作の説明と、最後の投げの結果（後ろ／前／クリティカル）が出る
3. 手前に並んでいる4人は**リングの形とチームの色の見本**（動かない）
4. まわりの茶色い箱が物資。場外に落ちても6秒で元の場所に戻る

> マウスで狙うときは、まず **Game ビューを1回クリック**する（カーソルが閉じ込められて、マウスの動きが届くようになる）。
> Escape でポーズ画面を開くとカーソルが戻る。

### 宇宙ごみのオンラインで遊ぶ（2026/10/28。2026/11/3 から設定なし）

1. タイトルから入る（プラクティスでも、部屋を作っても、部屋に入ってもよい）。**人のプレイヤーは全員この体で出てくる**
2. ボットを足すと、**ボットは今の体（フック）のまま**出る（ボットの頭はフックの部品で動くため）

> 2026/10/28〜11/2 はポーズ画面の「設定」→「プレイヤー：今の体／新しい体」で選ぶ形だった。小野田さんの依頼で、**項目ごと無くして、いつも新しい体にした**（2026/11/3）。
> 起動の引数 `-sweeper` も要らなくなったので無くした（付けても何も起きない）。
> **10/28 より前の版で作ったビルドとはつながらない**（通信の一覧に新しい体を足したため）。検証用のビルドは作り直すこと。

オンラインでの決まり：

| こと | どうなる |
| --- | --- |
| 名前 | 今の頭の上の名前のタグ（チームの色。始まりの演出で大きくなる）をそのまま使う |
| リングの形 | **チームの中で何人目か**（ロビーで入った順）で 円 → 三角 → 四角 → 星 → 六角形 |
| チームの色 | リング・顔の板・光線・狙いの帯。体（キャラクターダミー）はモデルのままの色 |
| ほかの人の画面 | 狙いの帯・光線・巻き取り・クリティカルの光が、本人と同じように見える（狙いのカーソルは本人にしか出ない） |
| 物資を引っ張る | 当たったらホストに「引っ掛けたい」と頼み、**認められてから 1.5 秒を数える**。ほかの人が引っ張っている物資はすり抜ける |
| 投げる | 自分の画面で計算した速さ（頭を越える放物線・前へ）を、そのままホストに渡す。ゴールに入ったかはホストが決める |
| 重いデブリ | **引っ張れない**（壁と同じで光線が戻る） |
| 試合・始まりの演出・ロビーの端末・R キーの復活時間 | 今の体と同じように止まる。止まったら出していた光線はしまう（つかんでいた物資は投げずに離す） |
| ベルトコンベア・列車・隕石・吹き飛ばす爆弾・動く床・回る床 | 今の体と同じように効く（今の体の歩く部品を「重力と吹き飛ばしの受け口」として残してあるため） |
| R キー・落ちたとき | 今の体と同じく出てくる場所へ戻る。出していた光線はしまう |

## 設定できる値（インスペクターの項目）

## 仕組み（分かる人向け）

- **部品を分けている**：移動（`SweeperMover`）・狙い（`SweeperAim`）・撃つ（`SweeperShooter`）・引き寄せ（`SweeperReel`）・見た目（リング・名前・帯）。
  `SweeperShooter` が段階（Idle → Charging → Extending → Retracting／Reeling）を持ち、撃ったら `SweeperMover.MoveLocked` を ON にして歩けなくする。
  狙っている間と光線が出ている間は `SweeperMover.FaceAim` を ON にして、狙う方向を向かせる。
- **マウスのカーソル**：カーソルを `CursorLockMode.Locked` で閉じ込め、マウスの動いた量（`Mouse.delta`）でプレイヤーから見たカーソルの位置を動かし、半径で切る。
  1台で複数人（席）・ボットのときは、画面のポインターを地面に映して半径で切る。
- **リング**：床に寝かせた板に、形までの距離を計算するシェーダー（円・正多角形・五芒星の距離の式）で描く。画像は使わない。色・形は `MaterialPropertyBlock` で渡す。
- **矢印の帯**：細長い板の UV の横を「長さ ÷ 矢印1枚の長さ」まで伸ばし（例：UV × 10）、画像の Wrap Mode を Repeat にして繰り返す。先に矢印の先の画像を1枚付ける。白い画像に色を掛ける。
- **引き寄せ**：毎物理ステップ、物資の横の速さを「止める位置までの残りの距離 ÷ 残りの時間」にする。縦は重力のまま（床に置いたまま引きずる）。だから距離に関係なく同じ時間で着く。
  正しくは、プレイヤーから見た物資の**距離**と**向き**を、それぞれ「残りの時間のうちの1ステップぶんの割合」だけ行き先へ近づけている（2026/11/4）。
  向きの行き先は「しなりの向き」なので、向きを変えていなければ今までと同じ計算になり、変えていれば物資がまわりを回り込む（回る速さは Max Swing Speed まで）。
- **しなり**（2026/11/4）：`SweeperShooter` が「手元から光線が出る向き」を持ち、巻き取りが始まった瞬間は物資への向き（＝まっすぐ）にする。
  あとは毎フレーム、体の向きへ**減衰するばね**で近づける（遅れて付いていき、少し行き過ぎて戻る）。物資への向きとの差は Max Bend Angle までに抑える。
  光線は `LiquidBeam.Follow(根元, 先端, 根元から出る向き, 強さ)` で描く。まっすぐな流れの点（らせん・ゆれ・しぶき・ライトも）を、2次ベジェの曲線の上に移して描く。
  曲線の真ん中の目印を、まっすぐのときの中点から「根元から出る向きへ長さの半分進んだ所」へずらすので、ずれが 0 なら今までとまったく同じまっすぐの線になる。
  光線の下り坂（手元のほうが物資より高い）の傾きは残し、横の向きだけをずらす（向きを変えていないのに上下に曲がらないように）。
  ほかの人の画面でも、通信で届く体の向きから同じように計算する（新しく配る値は無い）。
- **後ろへ投げる**：押した瞬間の位置から、頭より高い頂点を通って後ろの決まった距離に落ちる速さを、重力から逆算して与える（`Physics.gravity` を使う）。
  飛ぶ向き（2026/11/4）は、「体の真後ろ」から「物資がいま動いている向き」へ、その間の角度の Throw Follow Motion 倍だけ回したもの。
  動いている向きには、引き寄せで毎回決めている横の速さ（`FixedUpdate`）を使う。`Rigidbody` の速さは、ぶつかった跳ね返りが混ざるうえ、通信中に物理が止まっている物資では取れないため。0.5 m/秒より遅いときは真後ろにする。
  落ちる場所は、物資からその向きにまっすぐ進み、プレイヤーの中心から Back Distance 離れた所（まっすぐ引いているときは今までと同じ場所になる）。
  **注意**：残り時間が短いほど回り込みが速くなるので、受付のころに向きを変えていると横向きの勢いが大きくなる。Throw Follow Motion を 1 にすると、クリティカルがほぼ真横へ飛ぶことがある。
  クリティカルの衝撃波の向きは、今までどおり「プレイヤー→物資」の向き（飛ぶ向きとは少しずれることがある）。
- **クリティカル**：当たってからの時間が「受付の始まり〜長さ」の間に押されたら、クリティカルの距離と高さで投げ、エフェクトを出す。
- **クリティカルの仮のエフェクト**（2026/11/4）：合図は「受付の始まり − Cue Lead」の瞬間に1回だけ知らせ（オンラインではほかの人にも）、
  縮んでくる輪と金色のフチは、それぞれ Cue Lead 秒で受付の始まりに合わせて形が決まる（時間の値は、それぞれの画面の体のインスペクターの値を使う）。
  巻き取りが終わったら（押した・やめた）すぐ消える。ほかの人の画面では、本人から届いた「巻き取っている物資」（`SweeperShooter.ShownReelItem`）で見る。
  金色のフチと白い光は、物資の形（MeshFilter）を各軸に同じ厚みだけ大きくした写しを物資の子に作り、裏だけ描く（＝はみ出たフチだけ見える）／表を描く（＝全体が光る）で塗り分けている。
  推進の衝撃波は、プレイヤーから物資へ向かう向き（引っ張られている側の逆）に縦の輪を出し、飛び始めてからは 0.35 秒だけ進む向きの後ろから輪を出し続ける。
  一瞬止める（Hit Stop Seconds）は、その物資の速さを 0 にしてから投げる。止めている間はもう巻き取りは終わっていて、オンラインのホストへ「投げた」を送るのもその秒数だけ遅れる。

## できていないこと・既知の問題

- **人が遊んでの確認はまだ。** AI はコンパイルが通ることと、検証シーンが作れることを確認した。
  オンラインは、ホストと参加者を1つの Unity でつなぐ自動テストで「光線 → 引っ掛け → 引き寄せ → 押して後ろへ投げる」と体の切り替えを確かめた（2026/10/28）。**別々のPCでつないで遊んだ確認はまだ。**
- **宇宙ごみのオンラインの人のプレイヤーは、2026/11/3 から新しい体だけ**（小野田さんの依頼。プレイヤーの挙動を新しい体で詰めていくため）。今の体に戻す設定は無い。
  戻したくなったら、`SweeperOnlineSwitch` を消す（または入れ替えをやめる）だけで NetworkManager の Player Prefab（今の体）に戻る。
- ポーズ画面の「操作タイプ」「レティクル」「投げ方」は**今の体（フック）にしか効かない**ので、人のプレイヤーには今は何も変わらない（項目は残してある）。
- オンラインでは名前とチームを `SweeperNetSync` が `SweeperPlayer.SetProfile(名前, チーム)` に入れている。検証シーンでは手で入れる。
- 引っ張れるのは物資（`HookableObject`）だけ。重い物・大型物件・爆弾の扱いは後で（重いデブリはオンラインでも引っ張れない）。
- **オンラインで、ほかの人が引っ張っている物資の横取りはできない**（すり抜ける）。今の体の横取り・ZRワンボタン・操作タイプBの引き寄せは新しい体には効かない。
- オンラインで光線が当たってからホストの返事が来るまで（ほんの一瞬）は、押しても何も起きない。
- ボットは新しい体にならない（今の体で出る）。
- **白い画像に色を掛けているので、もとの絵の「白い内側の矢印」もチームの色になる**（塗りと区別が付くのは黒の縁だけ）。白いまま残したくなったら、内側だけ別の色にした画像を作り、シェーダーで塗り分ける。
- リングは床の少し上に板を置いて描いている。床に段差・坂があると浮いたり埋まったりして見える。床の中から直接描く（URP のデカール）には、全員共通の描画設定（`PC_Renderer`）を変える必要があるので、やるなら大槻さんに相談する。
- 光線の当たりは足元から 0.6m の高さの水平な線で見ている。坂の上の物資や、とても低い物資には当たりにくいことがある。
- クリティカルの合図・決まったときの光は**仮のエフェクト**（縮んでくる輪・金色のフチ・星のかけら・白い光・推進の衝撃波。2026/11/4）。最終的な見た目はデザインの方針なので、プロジェクトリーダー（デザイナー）に確認する。
- **金色のフチは箱の形の物資できれいに出る。** 丸い物や細かい部品の多い物は、フチの太さにむらが出る。
- `SweeperOutline.shader` はマテリアルのファイルを作らず、再生中に名前で探している。**ビルドではシェーダーが入らず、フチと白い光が出ないことがある**（リスクリスト）。
- マウスのカーソルを閉じ込めているので、エディタで再生中にほかの窓を触るときは Escape（ポーズ）でカーソルを戻す。
- **キャラクターダミーの大きさ（2026/11/4。Hansさんの了承済み）**：元のモデルは高さ約 0.34m なので、2つのプレハブの子 `Model` を **6倍**（高さ約 2.03m）にし、
  置き場所を上へ 0.01m・後ろへ 0.216m ずらした（2つのプレハブで同じ値）。当たり判定（CharacterController）もモデルに合わせて
  **高さ 2.03m・半径 0.45m・中心の高さ 1.02m** にした（半径は胴と頭の幅。Tポーズの腕は入れていない）。
  中心は前後にずらしていない（ずらすと、その場で向きを変えたときに当たり判定が円を描いて動き、壁に引っかかりやすくなるため）。
  **モデルの大きさ・向き・色を変えるときは、今後も Hansさん本人の了承が要る。** 顔の板・頭の上の物の高さはまだ合わせていない。
- 顔の板（FrontMark）はカプセルのときの位置（高さ約 1.5m／オンラインの体は約 1.25m）に残っていて、小さいモデルの上に浮いて見える。
  オンラインの体ではチームの色を塗る場所なので消していない。モデルにチームの色を付ける方法（Hansさんの `CharacterColor` など）が決まったら消してよい。
- **キャラクターダミーは動かない置物（アニメーションも骨も無い）。** `SweeperAnimation` は Animator が無いので何もしない。
- Hansさんのブランチ `feature/Hans-Stage01-ver01`（develop には未取り込み）に、**同じ場所・同じ名前の新しい版のモデル**（ファイルの中身が違う）と、キャラクター用のマテリアルがある。
  取り込むときにモデルとその `.meta` がぶつかるので、**Hansさんの版を選べばよい**（`.meta` の GUID は Hansさんの版にそろえてあるので、プレハブの参照は外れない）。
