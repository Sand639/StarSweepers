## この機能は何か

**参加したプレイヤーに「前・中・後」の語を組み合わせた名前を付け、全員の画面に同じ名前を出す。**

- 例：「漆黒」＋「の」＋「アリス」＝「漆黒のアリス」
- 名前はロビーの参加者・チーム分けの一覧と、プレイヤーの頭の上に出る。
- 名前を覚えるのはプレイヤー本人の部品。覚えるのは文字列ではなく、各語の番号3個。
- 現在は参加時のランダム命名。名前を自分で選ぶ画面はまだ作っていない。
- 同じPCの2人目以降にも、それぞれの名前を付ける。デバッグ用のボットの表示は従来の「BOT 1」など。

## 遊ぶ人から見た動き

| 操作 | 結果 |
| --- | --- |
| ホストとして開始／ほかの部屋へ参加 | ホストがその人の名前を1つ選び、全員へ配る |
| 途中から参加 | すでに参加している人の名前も届く |
| マップへ移動／ロビーへ戻る | 同じプレイヤーが残るので、名前も残る |
| チームが変わる | 頭の上のタグの色が変わる。名前は変わらない |

タイトル画面の従来の自由入力名は、現在のランダム名には使わない。

## 設定できる値（インスペクターの項目）

- `NameDataManager` の **Csv File**：使う名前の一覧。未指定なら `Resources/PlayerNames.csv` を読む。
- 名前タグの高さ・文字の大きさ・影・自分の名前を出すかは、従来どおり `PlayerNameplate.prefab` で調整できる。
- 検証用表示の **Start As Client**：OFFなら再生時にホスト、ONなら **Host Address** の相手へ接続する。

**決まり：** CSVの列は `Prefix,Connector,Suffix`。空のセルは候補に入れない。各列に最低1つの候補が必要。番号は0からで、全員が同じ一覧と並び順を使う。

## 仕組み（分かる人向け）

1. `NameDataManager.LoadCSV()` が一覧を読む。NetworkManagerに部品が無い検証環境では、Playerが同じNetworkManagerに補う。
2. `FishingNetPlayer.OnNetworkSpawn()` のホスト側で `RandomName(out prefix, out connector, out suffix)` を呼ぶ。
3. Playerの `SetName(prefix, connector, suffix)` が番号を検査し、3つの `NetworkVariable<int>` に保存する。書き込みはサーバーだけ。
4. `NamePrefixIndex`／`NameConnectorIndex`／`NameSuffixIndex` で番号を読める。`DisplayName` はその番号を `NameDataManager.GetName()` で文字列に戻す。
5. `SpaceJunkSession.NameOf(playerKey)` がPlayerの名前を返す。既存の一覧・タグ・名前を使うリアクションも、この入口を使う。ロビーの更新判定も現在の表示名を含む。
6. 以後の改名処理は `player.SetName(前の番号, 中の番号, 後の番号)` を呼ぶ。本人のPCからは所有者限定のRPCでホストに依頼し、ホストが改めて番号を検査する。他人のPlayerからの変更は受け付けない。

`SetName` の戻り値は、ホストでは変更できたか、参加者では要求を送れたか。未出現のPlayer・候補外の番号はfalse。名前の同期はNetcodeの保存された値を使うので、遅れて参加した人にも届く。

従来の `SpaceJunkPlayerSlot.Name` と、設定の自由入力名を送信・送り直しする処理は削除した。席は参加者番号とチームだけを持つ。名前の正本をPlayerに1つだけ置くため。

## 確かめ方

- `Assets/Scenes/Test/PlayerNameTest.unity` を開いて再生すると、自動でホストになり、名前と3つの番号が表示される。製品のビルド一覧には追加しない。
- シーンがまだ無い環境では `Tools > StarSweepers > プレイヤーの名前 > 検証シーンを作る`。すでにあるシーンは上書きしない。
- 2台で確認する場合、2台目は `PlayerNameTest` の **Start As Client** をONにし、**Host Address** にホストのIPを入れる。専用ポートは17984。
- バッチ再生の確認は `-executeMethod PlayerNameTestSetup.VerifyScene`。成功時はログに `[NAME] SCENE VERIFIED` を出し、終了コード0で終わる。
- Unity Test RunnerのEditModeで `NameDataManagerTests` と `PlayerNameNetworkTests` を実行できる。後者はテスト中にPlayModeへ入り、実際のホスト・客側と `SpaceJunkSession.NameOf` を検証する。

## できていないこと・既知の問題

- 自分で名前を選ぶ画面、次回起動後も同じ名前を覚える仕組み、名前の重複を防ぐ仕組みは未実装。
- 名前一覧の並びを変えると、同じ番号が別の名前になる。公開済みの番号を使い続ける場合は順番を変えないこと。
- 候補が足りない場合は警告を出し、「プレイヤー1」などの仮の名前で動き続ける。
- 壁の向こうのタグも見える（従来どおり）。
- 実機2台での見た目と、ロビーから全マップへの往復は手動確認していない。
