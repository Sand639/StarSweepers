# 移動床のオンライン同期 実装計画

> **実行時の必須スキル:** `superpowers:executing-plans` を使い、各タスクを順に検証しながら進める。

**目的:** `PullAblePlate` をホスト権限で移動・同期し、オンライン時にも床とプレイヤーが正しく追従し、複数回引いても壊れない状態にする。

**構成:** クライアントは引っ張り要求だけを ServerRpc で送り、ホストが衝突判定と移動を実行する。床の位置はサーバー権限の `NetworkTransform`、移動中状態は `NetworkVariable<bool>` で同期する。床上のプレイヤーは各端末が自分の所有プレイヤーだけを床の受信移動量に合わせて動かす。

**使用技術:** Unity 6000.3.14f1、Netcode for GameObjects、Unity Physics、Unity Test Framework（EditMode）

**作業上の制約:** ユーザーの個別指示を優先し、commit と push は行わない。編集する Scene は `STAGE_05.unity` だけとし、ほかの Scene は開いて保存しない。`MovableBlock` は変更しない。

---

## Task 1: オンライン移動権限と移動中状態をテストで固定する

**対象ファイル**

- 変更: `StarSweepers/Assets/Scripts/SpaceJunk/Editor/PullAblePlateTests.cs`
- 変更: `StarSweepers/Assets/Scripts/SpaceJunk/PullAblePlate.cs`

### 1. 失敗するテストを追加する

`PullAblePlateTests.cs` に、次を検証するテストを追加する。

- `PullAblePlate` が `NetworkBehaviour` である。
- `NetworkObject` と `Rigidbody` が必須コンポーネントとして宣言されている。
- 方向指定とプレイヤー位置指定の ServerRpc があり、どちらも `RequireOwnership = false` である。
- 移動中状態を同期する `NetworkVariable<bool>` を持つ。
- オフラインでは従来どおり直接移動できる。

### 2. 対象テストが意図どおり失敗することを確認する

Unity EditMode Test を `PullAblePlateTests` に絞って実行する。失敗理由が「オンライン用の型・RPC・同期状態が未実装」であることを確認する。コンパイルエラーや既存テストの予期しない失敗なら、テスト側を直してから先へ進む。

### 3. ホスト権限の要求経路を実装する

`PullAblePlate.cs` を `NetworkBehaviour` に変更し、次を実装する。

- 未 Spawn の場合は従来のローカル移動を維持する。
- Spawn 済みのクライアントでは、`Pull` / `PullToward` が ServerRpc を送るだけにする。
- Spawn 済みのサーバー／ホストだけが移動コルーチン、衝突判定、`Rigidbody.MovePosition` を実行する。
- 方向指定 RPC では、サーバー側でも柱の有効状態と方向を再検証する。
- プレイヤー位置指定 RPC では、受け取ったワールド座標と現在の床位置からサーバー側で方向を再計算する。
- 同時要求は最初の1件だけ受け付け、移動中の要求を無視する。
- `IsMoving` は未 Spawn 時のローカル値と Spawn 時の `NetworkVariable<bool>` を使い分ける。
- Disable / Despawn / 中断時に移動中状態を安全に解除し、次の操作が永久にできなくならないようにする。

### 4. 対象テストを再実行する

`PullAblePlateTests` がすべて通り、既存のオフライン向け挙動テストも維持されていることを確認する。

## Task 2: 床上プレイヤーを所有端末だけで追従させる

**対象ファイル**

- 変更: `StarSweepers/Assets/Scripts/SpaceJunk/Editor/PullAblePlateTests.cs`
- 変更: `StarSweepers/Assets/Scripts/SpaceJunk/PullAblePlate.cs`

### 1. 追従権限の失敗テストを追加する

追従対象の判定を純粋な方針関数としてテストできる形にし、次の表を固定する。

| 状態 | この端末で動かすか |
| --- | --- |
| オフラインのプレイヤー | 動かす |
| オンライン・自分が所有するプレイヤー | 動かす |
| オンライン・他人が所有するプレイヤー | 動かさない |
| NetworkObject を持たない既存テスト用プレイヤー | 従来どおり動かす |

あわせて、最初の同期フレームでは過去位置との差分を使わず、床が瞬間移動したような追従を起こさないことを検証する。

### 2. 失敗理由を確認する

対象テストを実行し、オンライン時の所有者判定と受信差分追従が未実装のため失敗していることを確認する。

### 3. 受信した床移動量でプレイヤーを追従させる

`PullAblePlate.cs` に次を実装する。

- オンライン時は各端末で床の前回位置を記録し、受信した位置差分だけ PassengerArea 内のプレイヤーを動かす。
- `NetworkObject.IsSpawned && !NetworkObject.IsOwner` のプレイヤーは、その端末では動かさない。
- ホスト側も同じ経路で自分のプレイヤーだけを動かし、移動処理中の直接追従と重複させない。
- Spawn 直後、Enable 直後、Despawn 後は観測位置を初期化し、初回差分による飛びを防ぐ。
- オフライン時は現在の `ApplyMoveStep` から全プレイヤーを追従させる挙動を維持する。

### 4. 対象テストを再実行する

所有者別の追従テスト、既存の PassengerArea テスト、複数回移動後の再操作テストがすべて通ることを確認する。

## Task 3: Prefab に同期コンポーネントを設定し、STAGE_05 の Scene ID を確定する

**対象ファイル**

- 変更: `StarSweepers/Assets/Scripts/SpaceJunk/Editor/PullAblePlateTests.cs`
- 新規: `StarSweepers/Assets/Scripts/SpaceJunk/Editor/PullAblePlateOnlineSetup.cs`
- 新規: `StarSweepers/Assets/Scripts/SpaceJunk/Editor/PullAblePlateOnlineSetup.cs.meta`
- 変更: `StarSweepers/Assets/Prefabs/SpaceJunk/Gimmick/PullAblePlate.prefab`
- 変更: `StarSweepers/Assets/Scenes/Prototype/SpaceJunk/Stage/STAGE_05.unity`

### 1. Prefab と Scene ID の失敗テストを追加する

次を検証する EditMode テストを追加する。

- Prefab ルートに `NetworkObject` がある。
- Prefab ルートに `NetworkTransform` があり、Authority が Server である。
- Position X/Y/Z は同期し、Rotation と Scale は同期しない。
- `STAGE_05.unity` 内の `PullAblePlate` の `GlobalObjectIdHash` と `InScenePlacedSourceGlobalObjectIdHash` が 0 ではない。
- Scene 内の NetworkObject ID と衝突していない。

Scene テストは Additive で開き、検証後に閉じて、テスト実行だけで別 Scene を保存しない。

### 2. 失敗を確認する

対象テストを実行し、Prefab に NGO コンポーネントがなく、Scene 配置 ID が未生成であるため失敗することを確認する。

### 3. Unity Editor 用の安全な設定処理を実装する

`PullAblePlateOnlineSetup.cs` に、Unity API で次を行う処理を実装する。

- `PullAblePlate.prefab` を `PrefabUtility.LoadPrefabContents` で開く。
- 既存設定を保ったまま、不足している `NetworkObject` と `NetworkTransform` だけを追加する。
- `NetworkTransform` を Server Authority、Position X/Y/Z 同期、Rotation/Scale 非同期に設定する。
- Prefab を保存して閉じる。
- `STAGE_05.unity` だけを開き、配置済み Plate の `NetworkObject.OnValidate` を Unity Editor 内で実行する。
- Scene を Dirty にして保存し、0 ではない配置 ID を確認する。
- 対話実行時には元の Scene 状態を壊さないよう、未保存 Scene がある場合は処理を中止して案内する。

### 4. Unity から設定処理を実行する

Unity 6000.3.14f1 をバッチモードで起動し、設定処理を1回実行する。実行ログに Prefab 保存、`STAGE_05.unity` 保存、生成された Plate ID を出す。

### 5. Prefab / Scene テストを再実行する

対象テストがすべて通ることを確認する。`git diff --name-only` で、意図せずほかの Scene や Prefab が保存されていないことも確認する。

## 自己レビューで特に確認する点

- Host で床を動かしたとき、床上の Host プレイヤーを「物理移動処理」と「受信差分処理」の両方で二重に動かしていないか。
- Client が受信する最初の `NetworkTransform` 更新で、古い初期位置との差分によりプレイヤーが飛ばないか。
- 移動中に Disable / Despawn / Network shutdown が起きても、次回 Spawn 後に永久ロックしないか。
- Scene 配置 NetworkObject の ID が 0 ではなく、既存 ID と重複していないか。
- 他人所有の Player を Host や別 Client が直接動かし、位置同期と競合していないか。
