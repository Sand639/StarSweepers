# 隕石攻撃 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 複数の床範囲から安全な落下点を選び、オンラインで同期した隕石がプレイヤー・得点素材・爆弾を吹き飛ばす仕掛けを作る。

**Architecture:** Host専用の `MeteorManager` が `MeteorArea` から落下点を選び、NetworkObjectの `MeteorStrikeEvent` を1つだけ生成する。EventはServerTimeで予告と着弾をそろえ、プレイヤーは各所有者側、物資と爆弾はHost側で処理する。

**Tech Stack:** Unity 6000.3.14f1、C#、Netcode for GameObjects 2.13.2、Unity Test Framework

**Spec:** `Documents/機能ドキュメント/隕石攻撃.md`

## Global Constraints

- Unityのバージョンは `6000.3.14f1` から変更しない。
- ランタイムスクリプトは `Assets/Scripts/SpaceJunk/` に置く。
- プレハブは `Assets/Prefabs/SpaceJunk/Gimmick/Meteor/` に生成する。
- 同時に存在できる隕石攻撃は1つだけ。
- 可拉扯大型方塊は動かさない。
- ユーザーの既存指示に従い、自動commit・pushは行わない。

## Review Focus

- 攻撃半径がAreaの半分以上なら、そのAreaを候補から外す。
- 回転・拡大縮小したAreaでも、攻撃円全体がBoxCollider内に収まる。
- Active Areasが空またはすべて無効でも例外を出さず待機する。
- Clientが物資へ力を加えず、Hostだけが既存の所有権を回収して飛ばす。
- 爆弾は飛ばされたうえで導火線が全員に同期される。
