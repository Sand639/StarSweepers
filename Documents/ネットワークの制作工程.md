## ⚠️ 先に決めること：誰が勝敗を決めるか

**これは工程4より前に決める。あとから変えると全部作り直しになる。**

> **2026/9/3時点：下の「混ぜる形」で実際に作ってある。**
> アイテムの得点と、押せる箱の物理は**ホストが決めている**。
> 動きだけ本人が送る形。**この形でよいかを、一度触って確かめてほしい。**

| やり方 | 内容 | 手間 | ズルへの強さ |
| --- | --- | --- | --- |
| **本人が全部決める** | 位置も点数も、動かしている本人が申告する | **軽い** | **弱い**（改造で何でもできる） |
| **ホストが全部決める** | 入力だけ送り、結果はホストが計算 | **重い**（ズレを隠す作り込みが要る） | 強い |
| **混ぜる（推奨・いまの形）** | **動きは本人、勝敗と点数はホストが決める** | 中 | **実用上は十分** |

### おすすめ：混ぜる形

- **動き**（走る・曲がる・ジャンプ）… **本人が送る**（今のまま）。操作が軽くなる
- **勝敗に関わること**（ゴール判定・点数・アイテム取得・当たった判定）… **ホストが決める**

これなら、**点数を書き換えるようなズルは効かない。**
壁抜けのような移動のズルは残るが、**展示では起きないし、Steamで友達と遊ぶ分にも実害は小さい。**

> **完全に守ろうとすると、作る量が跳ね上がる。**
> 10人・15週間の作品では、そこに時間を使うより中身を作るほうがよい、という判断。

## 工程2：試合の流れを作る

**ジャンル未定でも作れる。次に着手すべきはここ。**

「待っている → 全員そろった → 始まる → 遊んでいる → 結果 → もう一回」
という**流れの管理**を作る。どんな対戦ゲームでも必ず要る。

| 作るもの | 内容 |
| --- | --- |
| 試合の状態 | 待機／カウントダウン／対戦中／結果 の4つを、**ホストが持って全員に配る** |
| 準備完了 | 各自が「準備OK」を出し、**全員そろったら始まる** |
| カウントダウン | 3・2・1 を全員の画面で揃える |
| 結果の集計 | ホストが集計して全員に配る |
| もう一回 | 結果画面から待機へ戻す |

**重さ：中。** 企画が決まる前に作っておけば、決まった瞬間に中身を乗せられる。

## 工程3：本番の画面を作る

**ジャンル未定でも作れる。**

いまの接続画面は**画面左上に文字とボタンを出しているだけの仮のもの**で、
展示で来場者に見せられる状態ではない。

| 作るもの | 内容 |
| --- | --- |
| タイトル画面 | 「LANで遊ぶ」「1人で練習」を選ぶ |
| ロビー画面 | **誰が入っているか**を4人分並べる。色・番号・準備状態 |
| 接続中の表示 | つなぎに行っている間の待ち表示 |
| つながらない時の表示 | **何が悪いのかを日本語で出す**（展示の担当者が対応できるように） |

**重さ：中。** デザイナーと組む部分でもある。

> **本番の操作は基本コントローラー**（2026/9/14・大槻さん）。本番の画面はマウスが無くても全部選べるようにすること。
> **プロトタイプの段階ではキーボードとマウスだけでよい**ので、いまのポーズ画面（マウス専用）は本番の画面を作るときに直せばよい。

## 工程4：ゲームの中身を同期する

**⛔ ジャンルが決まらないと作れない。ここが企画待ちの本体。**

| レースなら | 対戦アクションなら |
| --- | --- |
| 順位・ラップ数 | 体力・攻撃の当たり判定 |
| アイテムの取得と使用 | 攻撃の発生と命中 |
| コース復帰（落ちた時） | 復活 |
| ゴール判定 | 決着判定 |

**どれも「ホストが決めて全員に配る」形で作る**（上の「混ぜる形」）。

**重さ：大。** ここが一番時間を食う。

## 工程5：壊れたときの備え

**展示に出すなら必須。**

展示会場では、**ケーブルが抜ける・PCが固まる・お客さんが途中で帰る**が普通に起きる。

| 作るもの | 内容 |
| --- | --- |
| 誰かが抜けたとき | 残った人で続けるか、待機に戻すかを決めて実装する |
| ホストが落ちたとき | **全員が遊べなくなる。**待機画面に戻して案内を出す |
| 再接続 | 抜けた人がもう一度入れるようにする |
| 展示担当者向けの操作 | **強制的に最初から始め直す**手段（お客さんが入れ替わるため） |

**重さ：中。** 地味だが、**これが無いと展示当日に担当者が困る。**

## 工程6：インターネット越しの接続

**展示には不要。家で遊んでもらうためのもの。**

### 6-A：合言葉でつなぐ（Unity Relay）→ **✅ 完了（2026/9/3）**

**実際に合言葉でつながり、2人が同じ空間に出ることを確認済み。**
**遅れは56〜78ms**（画面を描かない状態で測った値。最初に測ったときは85ms前後）だった（LANは5〜22ms）。この数字は**ジャンル選びに効く**ので、
`機能ドキュメント/インターネットでの複数人プレイ.md` の「遅れの実測値」を読むこと。

| 作ったもの | 内容 |
| --- | --- |
| つなぎ方の追加 | **中継サーバー（Relay）経由**でつなぐ道を足した |
| 合言葉 | ホストが作った合言葉を相手が入れると入れる |
| 起動引数 | `-nethost` / `-netjoin ＜合言葉＞` |

**ゲームの中身は書き換えていない。** 変わるのは「つなぐ前の準備」だけ。

~~残り：Unity Cloud への登録~~ → **2026/9/3に大槻さんが登録済み。** 無料枠（同時接続50人・1人3GiB）も2026/9/14に確認済み（`インターネットでの複数人プレイ.md`）。

### 6-B：Steamのフレンド招待 → 未着手

Steamで配布するなら、**フレンドリストから誘えるほうが遊ばれる**。
合言葉を打ってもらうより手間が少ないため。

**急がなくてよい。** 6-Aで遊べるようになるので、Steam版を出す段階で足せばよい。
詳しくは `Steamでの配布について.md` を読むこと。
