## 何が変わったか

**プロジェクトの名前が `Mirai01` から `StarSweepers` に変わりました**（2026/9/28）。

| 変わったもの | 前 | 後 |
| --- | --- | --- |
| GitHubのリポジトリ | `Sand639/Mirai01` | **`Sand639/StarSweepers`** |
| Unityのプロジェクトフォルダ | `Mirai01/` | **`StarSweepers/`** |
| Unityのメニュー | `Tools > Mirai01` | **`Tools > StarSweepers`** |

**中身は変わっていません。** シーンもプレハブも、そのまま使えます。

---

## やること（上から順に）

### 1. 作業中の変更をコミット＆プッシュしておく

途中のものがあれば、**先に自分のブランチへコミットしてプッシュ**してください。
このあとの手順でフォルダの名前が変わるので、やりかけのまま進めると分かりにくくなります。

### 2. つなぎ先を新しいリポジトリに変える

リポジトリのフォルダで、次を1回実行します。

```bash
git remote set-url origin https://github.com/Sand639/StarSweepers.git
```

> GitHubは古いURLからの転送もしてくれますが、**分かりにくくなるので変えておくこと。**

### 3. 最新を取ってくる

```bash
git pull
```

これで、手元の `Mirai01/` フォルダが `StarSweepers/` に変わります。

### 4. **Unityのキャッシュ（Library）を消す** ← 一番大事

**フォルダの名前が変わると、Unityが持っている対応表（`Library` フォルダ）が食い違って、
「スクリプトが見つかりません（The referenced script is missing）」が大量に出ます。**
再生しても何も動かず、画面にUIも出なくなります（2026/9/28 に実際に起きました）。

直し方は簡単で、**Unityを閉じて、`StarSweepers/Library` フォルダを削除するだけ**です。

1. Unityを**閉じる**
2. エクスプローラーで `StarSweepers/Library` フォルダを**削除**（ゴミ箱に入れてよい）
3. Unity Hub からプロジェクトを開き直す

> `Library` は**Unityが自動で作り直すフォルダ**です。Gitにも入っていないので、消しても作業は消えません。
> ただし**作り直しに数分〜十数分かかります。** 待っている間は他のことをしてください。

### 5. Unity Hub に新しい場所を登録する

Hub の一覧には古い名前（`Mirai01`）が残っていることがあります。
その場合は一覧から消して、**「Add」から `…\StarSweepers\StarSweepers` を選び直して**ください。

### 6. 動くか確かめる

- `Assets/Scenes/Prototype/SpaceJunk/MainScene/TitleScene.unity` を開いて再生し、タイトル画面が出るか（2026/9/28 当時は `Scenes/Test/SpaceJunkLobby.unity` で確かめていた。いまはゲームがタイトルから始まる）
- メニューが **`Tools > StarSweepers`** になっているか

## 困ったときは

| 症状 | 直し方 |
| --- | --- |
| 「The referenced script is missing」が大量に出る／再生しても何も動かない | **上の手順4（`Library` を消して開き直す）** |
| Unity Hub にプロジェクトが出てこない | 手順5。`…\StarSweepers\StarSweepers` を Add で選ぶ |
| ビルドしたゲームが全画面で始まる／窓の大きさを変えられない | **最新を `git pull` してからビルドし直す**（2026/9/28 に設定を直しました）。急ぎなら `Alt + Enter` でも窓表示に切り替わる |
| ビルドしたゲームで音量などの設定が初期値に戻った | **名前が変わったため**。Windowsが覚えている設定は製品名ごとなので、1回だけ設定し直してください |
| それでも直らない | 大槻 海斗（Discord）へ。**そのときのUnityの画面と、出ているエラーの文章**を一緒に送ってください |

## なぜこうなったか（読まなくてもよい説明）

Unityは、シーンやプレハブから「どのスクリプトを使うか」を**番号（GUID）**で覚えています。
番号そのものはフォルダ名を変えても変わりません。**ファイルは壊れていません。**

ただし、Unityは**作業を速くするための対応表を `Library` フォルダに作りためて**います。
この対応表はフォルダの場所を前提にしているので、**フォルダ名が変わると食い違い**、
「番号は合っているのに、スクリプトが見つからない」という状態になります。
`Library` を消せば、Unityが作り直して直ります。
