### 名義をどうするか

**Steamでは「ストアページに出る名前」と「契約・入金の名義」が別物。**

| | 何になるか |
| --- | --- |
| **開発元 / 販売元（ストアページの表示）** | **自由に決められる。チーム名を入れられる** |
| Steamworksの登録名義・税務情報・銀行口座 | **個人**（法人でなければ） |

つまり、**お客さんから見える名前はチーム名、契約と入金は大槻さん個人**、という形にできる。
希望どおりの見え方になる。

> ただし、**売上が発生したときの税金は個人に紐づく。**
> 金額によっては確定申告の話になるので、**分配を決めるときは、そこも含めて話しておくこと。**

## ⏰ スケジュールの逆算（重要）

### よくある誤解

> **「アプリクレジットがあれば、ノータイムでストアページを作れる」**
> → **半分正しい。**

| やること | 待ち時間 |
| --- | --- |
| **アプリを作る（App IDをもらう）** | **待ち時間なし。**クレジットを引き換えればすぐ |
| **ストアページを書く・画像を入れる** | **待ち時間なし。**いくらでも編集できる |
| **ストアページを公開する** | **審査あり。3〜5営業日**（Valve公式の目安） |
| **発売する** | **さらに先。**下の2つの条件を両方満たすまで |

### 発売の条件（Steam公式）

| 条件 | 内容 |
| --- | --- |
| **① 「近日登場」が2週間** | ストアページを公開してから、**最低2週間**は発売できない |
| **② 支払いから30日** | **Steam Direct料金を払ってから30日**は発売できない（Valveが身元を確認するための期間） |
| ③ ビルドの審査 | ゲーム本体もValveの確認を通す |

> **①と②は同時に進む。** 30日と2週間を足す必要はない。
> **支払いがずっと前なら、②はすでに終わっている**可能性が高い。管理画面で確認すること。

```
発売したい日
  ↑ 2週間以上（「近日登場」の期間）＋ ビルド審査
ストアページ公開
  ↑ 3〜5営業日（審査）※公開したい日の7日前には出すこと（Valve推奨）
ストアページ提出
  ↑ 画像・説明文づくり ← ここが一番時間を食う（人力）
  ↑ 税務情報・口座の登録と承認
アプリを作る（待ち時間なし）
```

**発売したい日の、最低1か月前**には動き始めること。余裕を見るなら2か月。

> **正確な状態はSteamworksの管理画面に出る。** 必ずそこで確認すること。

### 💡 クレジットを使うのは、まだ待ったほうがよい

**アプリクレジットは1つしかなく、引き換えると戻せない。**
ゲームの中身がまだ決まっていない今、急いで引き換える理由は無い。

**ただし「準備」は先にできる。** 下の「今できること」を読むこと。

**ゲームが無くてもできる準備がある。しかも一番時間が読めない部分。**

- [x] ~~未提出なら提出する~~ → 提出済みだった
- [x] ~~承認が下りるのを待つ~~ → **税金情報は承認済み**だった
- [ ] 「支払いから30日」の条件を満たしているか確認する
- [ ] 銀行口座の中身が埋まっているか開いて確認する

**ここを先に片付けておけば、企画が決まったあとは画像と説明文だけで済む。**

#### どこで確認するか

**上部メニューの「ユーザーと権限」→「会社情報」。ページの一番下**に税務情報がある。

```
partner.steamgames.com/dashboard
  └ 上部メニュー … ダッシュボード ／ アプリとパッケージ ／ ツール ／
                    【ユーザーと権限】 ／ 財務情報
                       ↑ こっち          ↑ ここではない
```

ダッシュボード右側の**「ツールとリンク」**の中にある
**「会社情報の表示と編集」**からも同じ場所へ行ける。

> **⚠️ 「財務情報」ではない。**
> 上部メニューの「財務情報」は**売上レポートのツール**（別サイト `partner.steampowered.com`）で、
> **アプリを1本も持っていないと開けない。**
>
> ```
> Your publisher account does not have any apps associated with it.
> ```
>
> と出るが、**これは異常ではない。** アプリを作れば見られるようになる。

> **⚠️ 権限が要る。** 税務情報を見る・変えるには **Actual Authority（実権限）** が必要。
> 最初に手続きをした本人であれば持っているはず。持っていない場合は、
> 手続きをした人に頼むことになる。

#### 確認した結果（2026/9/3・大槻さん）

**「会社情報」を開いたところ、次の4項目があった。**

| 項目 | 状態 |
| --- | --- |
| パートナーの詳細 | あり |
| 署名済みの契約 | **署名済み**（NDAと配信契約は完了） |
| 銀行口座の詳細 | あり（**中身が埋まっているかは、開いて確認すること**） |
| **税金情報** | **✅ 承認されています** |

**つまり、段階0（アカウントまわり）はほぼ完了している。**
一番時間が読めない「税務情報の承認」が終わっているので、**あとはゲームを作るだけ。**

> **郵送先住所**（ダッシュボードの「重要なアクション」に出ているもの）は、
> 物理的な商品の発送やイベント案内のためのもの。**発売に必須ではない**が、
> 埋めておいて損はない。

### このプロジェクトの場合

| 出来事 | 時期 |
| --- | --- |
| マスターアップ | **2026年12月18日（金）** |
| 未来創造展での展示 | 2027年**1月25日ごろ**（1月下旬。正式な日程は未定。2026/9/14・大槻さん） |

> **展示の日に「ストアページのリンク」を渡すだけなら**、ストアページの審査（3〜5営業日。Valveは公開したい日の7日前の提出を推奨）に間に合えばよい。
> 年末年始はValveの対応が遅れる可能性があるので、**1月上旬にはストアページを審査に出す**つもりで、**12月中に画像と説明文を用意する**のが安全。
> **展示の日に発売まで済ませたい**なら、「近日登場」の2週間とビルドの審査があるので、**1月上旬にはストアページが公開されている**必要がある（12月中の提出が必要）。
> どちらもマスターアップ（12/18）の前後と重なるので、担当を分けておくこと。

**展示の当日にリンクを渡したい**なら、展示日から逆算する。

> **間に合わなくても手はある。** 発売前でも**ストアページだけ公開**しておけば、
> 「ウィッシュリストに入れてね」と案内できる。**リンクを渡す目的なら、これでも成立する。**

## 技術側でやること

| やること | 難しさ | 補足 |
| --- | --- | --- |
| Windows向けビルドを作る | **軽い** | 今のビルド手順とほぼ同じ |
| Steamworks SDK を組み込む | 中 | **一部できた（2026/10/6）。** Steamworks.NET を入れて、**フレンドの部屋を探す機能だけ**に使っている（`機能ドキュメント/Steamのフレンドのサーバー.md`）。App ID はまだ無いので、テスト用の 480 で動かしている。**App ID を作ったら、`StarSweepers/steam_appid.txt` と `SteamFriendsService.DevelopmentAppId` の数字を変える** |
| **家で遊ぶときの通信をどうするか** | **中** | 下を読むこと |
| セーブデータの置き場所 | 軽い | 展示用と家庭用で作りを変える必要は無い |

### 通信をどうするか（方針が変わる）

**Steamで出すなら、インターネット対戦は「Steamの仕組み」を使うのがよい。**

以前 Unity Relay を勧めたが、**Steam版を出すなら、そちらのほうが有利になる。**

| | Steamの通信 | Unity Relay |
| --- | --- | --- |
| 費用 | **無料**（Steamで出す限り） | 無料枠あり。**上限を気にする必要がある** |
| 招待のしかた | **Steamのフレンドを招待できる** | **合言葉を口で伝える**必要がある |
| つながりやすさ | Steamの中継網を使う。品質が高い | 十分だが、Steamほどではない |
| 弱点 | **Steam経由でしか動かない** | どこでも動く |

**「家で友達と遊ぶ」用途では、招待の楽さが決定的に違う。**
合言葉を打ってもらうより、フレンドリストから誘えるほうが遊ばれる。

そこで、**接続のしかたを3つ持つ**形にするのがよい。

| 遊び方 | つなぎ方 | 使う場面 |
| --- | --- | --- |
| **LANで遊ぶ** | IPを直接指定（**できている**） | **展示会場** |
| **Steamで遊ぶ** | Steamの中継を使う（**未着手**。2026/10/6 から、通信は Unity Relay のまま、**Steam のフレンドの部屋を一覧に出して参加コードで入る**ところまではできた） | **家庭** |
| 1人で練習 | つながない | チュートリアル・デバッグ |

> **2026/9/3に、Steamを使わない家庭用のつなぎ方（合言葉・Unity Relay）も作ってある**（`機能ドキュメント/インターネットでの複数人プレイ.md`）。
> Steam版を出すまでは、これで家から遊べる。Steamの通信は、Steam版を出す段階で4つ目のつなぎ方として足せばよい。

**ゲームの中身は3つとも同じ。** 変わるのは「つなぐ前の準備」だけなので、
今作った土台はそのまま使える。

> Netcode for GameObjects には、**Steamの通信につなぐための部品が有志から公開されている。**
> 導入するときは、`使用素材とライセンス.md` に記載すること（Unity公式ではないため）。

## 気をつけること

### 生成AIの開示

**Steamでは、生成AIを使った場合の開示が求められる。**
このプロジェクトは**プログラムをAI（Claude Code / Codex）に書かせている**ので、
**開示の対象になる可能性が高い。**

- 提出時のアンケートで、**何にAIを使ったか**を書く欄がある
- **絵・音・文章にAIを使った場合は、特にはっきり書くこと**
- 隠して出すと、あとで問題になる

> 学校のガイドラインも「**責任は制作者本人が負う**」としている。
> **隠さず書くのが、両方の要求を満たす唯一のやり方。**

### 素材のライセンス

**展示だけなら見逃されても、販売すると規約違反になる素材がある。**

- 「個人利用のみ」「商用利用不可」の素材が入っていないか
- クレジット表記が必要な素材を、ゲーム内に書いているか
- **`使用素材とライセンス.md` を、販売を決めた時点で全部見直すこと**

### 無料にするか、有料にするか

| | 利点 | 欠点 |
| --- | --- | --- |
| **無料** | 展示のお客さんが**その場で入れてくれる**。遊ばれる数が最大になる | 売上は無し |
| **安く売る** | 作品として値段が付く。実績になる | **展示のお客さんは、まず買わない** |

**「展示でリンクを渡して家でも遊んでほしい」が目的なら、無料のほうが目的に合う。**
ただし**チーム全員と学校の意向**があるので、勝手には決められない。
